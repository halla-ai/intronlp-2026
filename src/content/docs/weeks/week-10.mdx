### 9주차에서 이어지는 자리

9주차는 트랜스포머가 토큰 사이의 관계를 살피는 방법을 다룬 주차. 이번 주는 **어떤 문제로 미리 연습했는가**에 따라 같은 트랜스포머 계열도 쓰임이 달라진다는 점의 확인.

| 비교 | 9주차 | 10주차 |
|---|---|---|
| 핵심 질문 | 문맥에서 다른 토큰을 어떻게 참고하는가 | 무엇을 맞히도록 미리 학습했는가 |
| 살펴볼 것 | 어텐션과 문맥 표현 | 양방향 읽기와 자동회귀 생성 |
| 실습 범위 | 제공된 실행 결과 읽기 | 공개 모델의 분류·생성 결과 읽기 |

### 이 문서를 읽는 법

- 수식 없이 입력, 모델의 학습 과제, 출력의 차이부터 확인
- GPT는 이 문서에서 **모델 계열의 이름**으로 사용
- 기본 실습 입력은 [제주관광공사 VisitJeju 올레 6코스 안내](https://m.visitjeju.net/en/detail/view?contentsid=CNTS_000000000020298)의 첫 절 짧은 발췌. 열람일 2026-10-11
- 발췌 원문: `Jeju Olle Trail Route 6 is an 11-kilometer coastal and urban trail`. 원문 뒤에는 경로 설명이 이어지며, 실습에서는 절 끝에 마침표 추가
- `wonderful`과 `not wonderful` 문장은 사람이 작성한 **감정 통제 예시**. 공식 원문·실제 후기·기업 데이터와 구분
- [제주 공개 데이터 출처](/reference/data/)에서 실제 안내 확인
- 그림은 학습 방식의 **모식도**. 숫자 없는 설명용 시연이며 실제 모델 추론 결과와 구분
- 모델의 실제 라벨·점수·생성문은 실행한 노트북에서 확인. 실행 전 정답 숫자나 생성문을 미리 제시하지 않는 방식

## 온라인 (2시수)

### 강의 1: 사전학습과 양방향 읽기

#### 사전학습은 무엇인가

관광 안내 업무에 새로 온 사람에게 제주 안내문을 한 장씩 읽히는 상황의 가정. 처음부터 읽기 자체를 가르치기보다, 이미 글을 읽을 줄 아는 사람에게 관광 안내 업무를 맡기는 편이 빠른 준비.

모델에서도 같은 구분. **사전학습**은 많은 글을 바탕으로 낱말의 연결과 문맥 패턴을 먼저 익히는 과정. 모델 안에 그 결과가 숫자로 저장된 상태를 가져와 사용하는 방식. 문서를 그대로 보관하는 공식 자료집과는 다른 구조.

- 사전학습 단계: 다양한 글에서 언어 패턴 학습
- 미세조정 단계: 이미 학습한 모델에 특정 과제의 예시를 추가해 과제에 맞게 조정
- 추론 단계: 완성된 모델에 새 입력을 넣어 결과 확인
- 이번 주의 범위: **추론만 실행**. 학습 코드 작성·실행 제외

이미 만든 도구를 빌려 쓰는 것과 새 도구를 만드는 것의 구분. 도구를 가져오는 비용도 필요하지만, 처음부터 모델을 학습하는 비용과는 다른 수준의 준비.

#### BERT: 빈칸 앞뒤를 함께 읽기

`Jeju has a [MASK] near the coast.`라는 설명용 문장의 가정. 빈칸 앞의 `Jeju has a`뿐 아니라 뒤의 `near the coast`도 빈칸을 판단하는 단서.

**BERT의 마스크 언어모델 학습**은 일부 토큰을 가리고 원래 토큰을 맞히는 연습. 가려진 위치를 판단할 때 좌우 문맥을 모두 참고하는 것이 양방향 읽기의 뜻. 여기서 빈칸은 원래 문장에 있었던 토큰을 복원하는 자리이지 사실 검색 결과가 아님.

<FigureFrame src="/interactive/week-10/context-direction.html" title="양방향 빈칸 읽기와 앞쪽 문맥만 보는 이어쓰기" height="350px" />

- 양방향: 판단할 위치의 앞과 뒤에 있는 문맥 활용
- 자동회귀: 다음 토큰을 판단할 때 이미 주어진 앞쪽 문맥 활용
- 같은 입력이라도 **판단할 자리와 볼 수 있는 문맥**의 차이
- 그림 속 선택은 문맥 범위 표시일 뿐, 실제 모델이 어떤 토큰을 예측할지의 증거가 아님

#### 빈칸 모델이 문장을 분류하는 이유

빈칸을 맞히도록 익힌 문맥 표현은 문장 전체의 특징을 파악하는 데 활용 가능. 그 위에 특정 라벨을 고르는 분류 기능을 붙이고 해당 과제에 맞게 미세조정하는 방식.

이번 노트북의 분류 모델은 **DistilBERT 계열을 영어 영화평 감정분류에 이미 미세조정한 모델**. 원본 BERT를 직접 실행하는 실습이 아니라, BERT 계열의 문맥 읽기 능력을 사용하는 경량 모델의 활용.

| 입력 예시 | 모델에게 요구하는 것 | 모델이 반환하는 것 |
|---|---|---|
| `The walk by the sea in Jeju was wonderful.` | 긍정/부정 중 하나 선택 | 감정 라벨과 해당 라벨의 score |
| `The walk by the sea in Jeju was not wonderful.` | 부정 표현까지 읽고 라벨 선택 | 감정 라벨과 해당 라벨의 score |
| `Jeju Olle Trail Route 6 is an 11-kilometer coastal and urban trail.` | 중립 설명에도 두 라벨 중 하나 선택 | 감정 라벨과 해당 라벨의 score |

위 표의 감정 문장 두 개는 부정 표현 비교를 위한 통제 예시이며 마지막 문장은 공개 관광안내 발췌. 위 표는 **입력과 출력 형식의 안내**. 실제 라벨과 점수는 노트북 실행 후 기록.

이 모델은 `POSITIVE`와 `NEGATIVE`만 선택. `NEUTRAL`이 없으므로 중립 문장에도 하나를 고르는 구조. `POSITIVE`는 "관광"이나 "바다"라는 주제 라벨이 아니라 감정 라벨.

#### 강의 1에서 꼭 가져갈 것

1. 사전학습, 미세조정, 추론의 구분
2. BERT의 빈칸 예측에서 앞뒤 문맥을 모두 참고하는 이유
3. 분류 결과를 해석하기 전 **학습한 과제와 라벨 목록**의 확인
4. 감정분류를 관광 주제 분류로 해석하지 않는 원칙

### 강의 2: 자동회귀 생성과 모델 선택

#### GPT: 한 토큰씩 이어 붙이기

`A visitor walking along the coast of Jeju Island`를 입력한 상황의 가정. GPT 계열은 이 앞부분을 보고 다음 토큰을 고른 뒤, 그 토큰을 입력 끝에 붙여 다시 다음 토큰을 고르는 방식.

**자동회귀**는 앞에서 나온 토큰까지 참고해 다음 토큰을 반복적으로 예측하는 방식. 9주차에서 본 어텐션도 다음 자리에 아직 없는 미래 토큰을 미리 볼 수 없도록 제한. 토큰은 단어 전체일 수도, 단어 조각일 수도 있는 단위.

<FigureFrame src="/interactive/week-10/autoregressive-steps.html" title="한 토큰을 붙인 뒤 그 결과를 다시 참고하는 생성 단계" height="320px" />

- 그림: 사람이 정해 둔 단어 조각을 붙이는 **설명용 모식도**
- 노트북: 사전학습 모델이 실제로 다음 토큰을 고르는 추론
- 생성 중 길이 제한에 도달하면 문장 중간에서도 종료 가능
- 매 단계의 그럴듯한 선택과 글 전체의 정확한 내용은 별개의 문제

#### 이번 실습의 생성 모델

**DistilGPT2**는 GPT-2 계열의 영어 이어쓰기 모델을 경량화한 공개 모델. 대화용으로 질문을 받아 정답을 알려 주는 과제가 아니라, 주어진 글 뒤를 이어 쓰는 과제.

- CPU 환경에서 사용할 수 있도록 짧은 입력과 최대 32개 새 토큰으로 제한
- `do_sample=False`: 매 단계에서 가장 높은 점수의 토큰을 선택하는 설정
- 동일 설정으로 반복 실행해 결과를 비교하는 방식. 소프트웨어 환경 차이까지 완전히 같다는 보장은 없음
- 실제 노트북의 시작 문장은 올레 6코스 공개 안내의 발췌. 원문의 다음 문장을 복원하는 과제와 구분
- 출력은 입력에 이미 있던 부분을 제외한 **새로 이어 쓴 부분**만 표시

생성문에서 제주와 무관한 이야기가 나오거나 같은 말이 반복될 수 있는 모델. `Jeju`라는 단어를 넣었다는 사실만으로 제주 전문 안내가 되는 것은 아님.

#### score와 사실성을 구분하기

분류의 `score`는 입력 하나에 대해 모델이 선택한 감정 라벨에 부여한 점수. 실제 정확도는 정답이 있는 여러 문장의 결과를 별도로 대조해야 확인 가능한 값.

생성도 비슷한 주의 필요. 언어 패턴상 자연스러운 문장과 공식 정보에 근거한 문장은 별개. 운영시간, 교통편, 가격이 생성되면 공식 공개 안내와 대조하기 전에는 미확인 주장.

<FigureFrame src="/interactive/week-10/model-fit.html" title="과제에 맞는 모델 선택과 사람 검토 판단" height="360px" />

#### 그대로 쓰기 전에 확인할 기준

인력과 장비가 적은 도내 조직을 **상정한 조건**에서 도구 선택. 실제 기업의 데이터나 운영 사례와는 구분.

| 확인 기준 | 조건이 맞는 경우 | 맞지 않는 경우의 다음 선택 |
|---|---|---|
| 입력 언어 | 영어 모델에 영어 입력 | 한국어를 지원하는 공개 모델부터 탐색 |
| 출력 라벨 | 필요한 결과가 긍정/부정 | 관광 주제처럼 다른 라벨이면 과제에 맞는 모델 탐색 |
| 내용의 사실성 | 창작용 초안이며 사람이 검토 | 공식 안내는 출처 대조와 사람 검토 필수 |
| 자원 | 짧은 입력과 CPU 추론 가능 | 더 작은 모델이나 규칙 방식 검토 |
| 확인용 데이터 | 공개 자료의 예시와 정답 준비 | 평가 자료부터 정리, 성능 단정 보류 |

새 모델을 처음부터 학습하는 결론보다 **과제에 맞는 공개 모델 선택, 공개 자료 정리, 기존 규칙 보완**부터 검토하는 순서. 미세조정이 필요한지는 평가 뒤의 판단이며 이번 실습에서 구현하지 않는 범위.

#### 강의 2에서 꼭 가져갈 것

1. GPT 계열의 생성은 다음 토큰을 반복적으로 이어 붙이는 방식
2. 이어쓰기 모델과 질문에 답하는 대화 모델의 구분
3. 분류 score와 실제 정확도, 생성문과 사실 확인의 구분
4. 모델을 그대로 쓰기 전 언어·과제·라벨·자원·검토 방식 확인

## 대면 (1시수)

### 노트북 그대로 실행하기

**필수 작업은 코드 작성이 아니라 제공된 노트북의 전체 실행과 결과 읽기**. 선택적으로 입력 문장 한 곳만 교체하는 방식.

1. 준비 셀 실행과 CPU 사용 확인
2. 모델의 이름, 버전, 영어 지원, 감정 라벨 확인
3. 공개 안내 발췌와 사람이 작성한 긍정·부정 통제 예시의 분류 결과 읽기
4. 제공된 시작 문장의 실제 이어쓰기 결과 읽기
5. 선택 활동: TODO의 짧은 영어 입력 문장 한 곳만 교체하고 전후 비교
6. 확인 질문에 실제 결과와 해석 기록

기본값을 바꾸지 않아도 끝까지 실행되는 골격. 모델은 각각 불러와 실행하고 메모리를 해제하는 방식. 처음 실행 시 네트워크로 수백 MB의 파일 다운로드 필요. GPU 설정과 모델 학습 불필요.

### 출력 읽는 법

- `status: ok`: 해당 추론의 실제 결과 반환
- `label`: 영화평 감정분류에서 학습한 긍정/부정 라벨
- `score`: 선택한 감정 라벨에 부여한 점수. 정확도·사실성·관광지 품질과 구분
- `continuation`: 입력 뒤에 새로 생성한 부분
- `status: unavailable`: 설치, 다운로드, 모델 불러오기 또는 추론 실패. **모델 결과 없음**

`unavailable`이 나와도 후속 셀을 읽을 수 있도록 구성. 하지만 모든 셀을 실행했다는 사실과 실제 모델 실험 성공은 다른 상태. 오류를 보존하고 해결 후 재실행 필요. 실패한 결과에 가상의 라벨이나 생성문을 채우지 않는 원칙.

### 자주 막히는 지점

| 증상 | 확인할 것 | 다음 조치 |
|---|---|---|
| 준비 셀에서 unavailable | 설치 오류의 마지막 줄 | 연결 상태와 런타임 확인 후 준비부터 재실행 |
| 모델 단계에서 unavailable | 다운로드·파일·메모리 오류 | 오류 보존, 원인 해결 후 해당 단계 재실행 |
| 처음 실행에 긴 대기 | 모델 파일 다운로드 여부 | 중복 실행하지 않고 현재 실행 대기 |
| 생성문에 무관한 내용 | 영어 이어쓰기 모델의 학습 과제 | 고장으로 단정하지 않고 과제 적합성 기록 |
| 중립 입력에도 긍정/부정 | NEUTRAL 없는 라벨 목록 | 결과를 중립 판단으로 해석하지 않고 한계 기록 |

## 확인 질문과 답

<details>
<summary>Q1. 빈칸 예측과 이어쓰기의 가장 큰 차이는?</summary>

빈칸 예측은 가려진 위치의 원래 토큰을 복원하는 과제. BERT는 이 위치의 앞뒤 문맥을 함께 활용. 자동회귀 이어쓰기는 이미 주어진 앞쪽 문맥으로 다음 토큰을 예측하고, 결과를 붙여 반복하는 과제.

</details>

<details>
<summary>Q2. 사전학습 BERT를 가져오면 관광 주제 분류가 바로 가능한가?</summary>

필요한 과제와 출력 라벨 확인이 먼저. 이번 모델은 영어 영화평의 긍정/부정에 미세조정한 모델. 관광 주제 라벨을 학습한 모델이 아니므로 감정 라벨을 관광 주제로 해석할 수 없음.

</details>

<details>
<summary>Q3. 중립 설명문을 POSITIVE로 분류하면 관광지가 좋다는 뜻인가?</summary>

아님. 모델이 선택할 수 있는 라벨은 긍정/부정 두 개뿐. 중립 설명에도 하나를 선택하며 영화평과 다른 관광 설명에서의 한계도 존재. 실제 관광지 평가로 해석 불가.

</details>

<details>
<summary>Q4. score가 높으면 정확도도 높은가?</summary>

입력 하나의 라벨 점수와 여러 정답 예시에서 측정한 정확도는 다른 값. 높은 score로 틀리는 사례도 가능. 정확도 확인에는 정답이 있는 별도 평가 자료 필요.

</details>

<details>
<summary>Q5. 자연스러운 제주 안내 생성문을 그대로 배포해도 되는가?</summary>

언어적으로 자연스러운 글과 사실에 근거한 안내는 별개. 지명, 운영시간, 가격, 교통편 등의 공식 출처 대조와 사람 검토 필요. 이번 모델의 목표는 영어 이어쓰기이며 제주 정보 검증이 아님.

</details>

<details>
<summary>Q6. 노트북이 마지막 셀까지 진행했는데 전부 unavailable이라면?</summary>

오류가 후속 실행을 막지 않았다는 확인일 뿐, 모델 추론 성공은 미확인. 실제 결과를 만들어 채우지 않고 오류를 보존. 원인을 해결한 뒤 분류와 생성 단계 재실행 필요.

</details>
