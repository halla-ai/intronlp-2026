## 이번 주차

- **학습목표**: 프롬프트 설계와 미세조정의 비용·효과 구분, zero-shot·few-shot 비교
- **실습목표**: 같은 자료·질문·모델에서 프롬프트 두 가지를 실행하고 보고서·발표 자료 작성
- **실습 범위**: 사용자 관점의 지시 작성과 실제 출력 확인. 모델 학습·검색 시스템 구현 제외
- **결과물**: 프롬프트 엔지니어링 미니 프로젝트 보고서와 발표

### 11주차에서 이어지는 자리

- 11주차: 예시를 넣거나 빼며 문맥학습과 근거 확인의 필요성 관찰
- 12주차: 그 관찰을 목적·자료·제약·출력 형식으로 정리하고 비교 결과 공유
- 공통 기준: 읽기 좋은 답과 원문으로 확인한 답의 구분
- **프롬프트를 정교하게 적어도 사실성 보장은 없음**. 실제 결과를 원문과 대조하는 절차 유지

| 비교 | 프롬프트 작성 전 | 프롬프트 작성 후 |
|---|---|---|
| 목적 | 무엇을 시킬지 막연한 상태 | 답변 대상과 질문 명시 |
| 자료 | 모델이 알아서 알 것이라는 기대 | 사용할 원문과 출처 제공 |
| 확인 | 문장이 자연스러우면 수용 | 주장별 근거와 확인 불가 항목 기록 |

### 이 문서를 읽는 법

- 그림의 선택 결과는 **사람이 작성한 교육용 안내**. 실제 모델 출력이나 성능 측정과 구분
- 자료는 [제주 공개 데이터 출처](/reference/data/)에 등록된 공식 공개 안내의 짧은 발췌
- 도내 조직은 인력·예산이 적은 **상정 조건**. 실제 기업 데이터·관광객 후기 사용 없음
- 모델의 실제 답은 실행 후 기록. 좋은 답이나 나쁜 답을 미리 만들어 실험 결과로 제시하지 않는 방식
- 이번 주에는 **별도 실습 노트북 없음**. 11주차의 제공된 실행 환경을 활용하고 기록 양식 작성

## 온라인 (2시수)

### 강의 1: 목적을 실행 가능한 지시로 바꾸기

#### 프롬프트의 다섯 부분

**프롬프트**는 모델에게 입력하는 지시와 문맥. 원하는 결과를 쓰는 것뿐 아니라 어떤 자료를 쓰고 어디까지 답할지 함께 정하는 작업.

| 부분 | 이번 프로젝트의 내용 | 확인 질문 |
|---|---|---|
| 목적 | 방문자의 질문에 짧게 답변 | 누구에게 무엇을 알려 주는가 |
| 자료 | 공식 안내 발췌 두 개 | 모델이 사용할 근거는 어디인가 |
| 제약 | 자료 밖의 가격·시간 등 추측 금지 | 모르는 내용을 어떻게 처리하는가 |
| 출력 | 답변·근거 ID·확인 상태 | 결과끼리 나란히 비교 가능한가 |
| 근거 | 원문의 해당 표현 표시 | 답을 뒷받침하는 문장이 실제로 있는가 |

역할 이름을 붙이는 것만으로 지식이 추가되지는 않는 구조. '제주 전문가'라는 지시보다 **공개 자료와 근거 확인 기준을 함께 제공**하는 편이 이번 과제의 목적에 맞는 선택.

<FigureFrame src="/interactive/week-12/prompt-parts.html" title="목적·자료·제약·출력·근거를 더하는 교육용 프롬프트 구성" height="430px" />

- 그림에서 각 부분을 켜고 끄며 지시의 차이 확인
- 표시되는 문장은 제공된 조각을 합친 결과. 모델 추론 실행 없음
- 지시가 빠진 상태에서 예상한 문제와 실제 모델 출력에서 본 문제의 구분

#### zero-shot과 few-shot

- **Zero-shot**: 과제의 답변 예시 없이 지시와 자료만 제공
- **Few-shot**: 입력과 원하는 출력의 예시를 소수 제공
- 두 방식 모두 실행 시 입력 문맥을 사용하는 방식. 모델 가중치를 다시 학습하는 과정 아님
- 예시의 역할: 말투·항목·확인 불가 처리 방식의 전달
- 주의: 예시가 있다고 정답률 상승이나 새로운 사실 학습을 단정할 수 없는 구조

'자료에 없는 것은 확인 불가로 남기기'라는 기준도 예시로 전달 가능한 내용. 예시를 넣은 답이 더 길어졌다고 더 정확하다고 볼 수는 없는 기준.

#### 이번 프로젝트의 공통 자료

다음 두 발췌를 **A와 B 모두에 동일하게 제공**. 출처 ID는 원문 대조를 위한 수업용 표기.

| ID | 공통 입력 자료 | 출처·가공 |
|---|---|---|
| H | `Hallasan. At 1,950 m above sea level, it is the highest mountain in South Korea.` | [한라산 공식 안내](https://www.visitjeju.net/en/detail/view?contentsid=CONT_000000000500685). 2026-10-11 열람. 원문 한 문장 발췌, 제목 `Hallasan.` 추가 |
| O | `Jeju Olle Trail Route 6 is an 11-kilometer coastal and urban trail.` | [올레 6코스 공식 안내](https://m.visitjeju.net/en/detail/view?contentsid=CNTS_000000000020298). 2026-10-11 열람. 첫 절 발췌 후 마침표 추가 |

- H의 앞에 추가한 제목과 O의 끝에 추가한 마침표는 수업용 가공
- 표의 원문 정보는 열람 시점의 안내. 최신 이용 조건을 대신하는 자료 아님
- 올레 페이지의 상단 설명은 13.3km, 상세 본문은 11km로 표기가 다른 상태. 실습은 제공한 상세 본문 발췌에 대한 답을 대조하며 실제 최신 코스 길이는 추가 확인 전 판단 보류
- 두 발췌에는 운영시간·요금·이동 소요시간 정보 없음
- 프로젝트는 주어진 자료 범위의 답변 실험. 실제 여행 의사결정 서비스로 배포하는 활동 아님

#### 같은 목적의 프롬프트 두 가지

두 프롬프트 모두 공통 자료와 질문을 사용. A는 예시 없는 지시, B는 **출력 예시 한 개를 더한 지시**. 비교 실험에서 달라지는 부분을 명확하게 남기는 구성.

**공통 골격**

```text
Purpose: Answer a visitor's question using only the supplied sources.
Sources:
[H] Hallasan. At 1,950 m above sea level, it is the highest mountain in South Korea.
[O] Jeju Olle Trail Route 6 is an 11-kilometer coastal and urban trail.
Rules: Do not add facts absent from the sources.
If the sources do not answer the question, write "Not stated".
Format: Answer | Source ID | Evidence
Question: {question}
Answer:
```

**프롬프트 A: zero-shot**

- 공통 골격의 `{question}`을 아래 질문으로 바꿔 실행
- 답변 예시 추가 없음

**프롬프트 B: few-shot**

- A와 같은 골격·자료·질문 사용
- `Question: {question}` 앞에 다음 예시만 추가

```text
Example:
Question: What is the admission fee for Hallasan?
Answer: Not stated | None | The supplied sources do not state a fee.
```

이 예시는 교수가 작성한 **형식 안내**. 실제 모델이 생성한 답이나 공식 요금 안내와 구분. B에서도 시험 질문의 정답을 예시로 주지 않는 구성.

#### 공통 비교 질문

| 번호 | A와 B에 동일하게 넣을 질문 | 원문 대조 기준 |
|---|---|---|
| 1 | How high is Hallasan above sea level? | H에 나온 높이 표현과 답의 단위 대조 |
| 2 | How long is Jeju Olle Trail Route 6? | O에 나온 거리 표현과 답의 단위 대조 |
| 3 | How many hours does it take to walk Route 6? | 두 발췌에 소요시간 없음. 거리에서 시간을 추측했는지 확인 |

정답 대조는 **원문의 표현 유무**를 기준으로 수행. 말투가 친절한지, 문장이 긴지는 별도의 관찰 항목.

### 강의 2: 프롬프트, 미세조정, 자료 연결의 구분

#### 같은 모델을 쓰는 것과 모델을 바꾸는 것

**미세조정(fine-tuning)**은 이미 학습된 모델에 과제별 학습 자료를 주어 가중치를 추가로 조정하는 과정. **프롬프트 설계**는 가중치를 유지한 채 추론 시 넣는 지시·문맥을 바꾸는 과정.

| 비교 | 프롬프트 설계 | 미세조정 |
|---|---|---|
| 바꾸는 것 | 입력 지시·예시·자료 | 모델의 가중치 |
| 준비 | 과제 설명과 확인용 예시 | 학습 자료, 학습 환경, 평가 자료 |
| 비용 | 입력 길이 증가에 따른 추론 부담, 작성·검토 시간 | 자료 정리·학습·평가·유지 비용 |
| 효과를 기대할 부분 | 한 요청의 형식·조건·문맥 전달 | 반복 과제의 행동을 학습 자료에 맞게 조정 |
| 보장하지 않는 것 | 사실성·항상 같은 출력 | 사실성·모든 새 질문의 정답 |
| 이번 수업 | 두 프롬프트의 실행과 비교 | 이름·목적·비교만 학습, 실행 없음 |

**무조건 싼 방식이나 항상 좋은 방식은 없음**. 프롬프트를 길게 반복하면 추론 부담이 늘고, 미세조정도 학습 자료의 오류·편향을 따라갈 수 있는 가능성.

<FigureFrame src="/interactive/week-12/method-choice.html" title="상정 조직 조건에서 비용과 효과를 구분하는 판단 연습" height="370px" />

인력과 예산이 넉넉하지 않은 도내 조직의 상정. 먼저 작은 공개 자료와 확인 질문으로 프롬프트를 시험하고, 반복해서 실패한 과제가 무엇인지 기록하는 선택. 이 기록 없이 새로운 학습의 비용·효과를 단정하지 않는 순서.

#### RAG: 찾은 자료를 답 생성에 연결하기

**RAG(검색 증강 생성)**는 질문에 관련된 자료를 검색하고, 그 자료를 모델 입력에 넣어 답을 생성하는 방식.

1. 질문에 관련된 자료 찾기
2. 찾은 자료를 질문과 함께 모델에 제공
3. 모델 답을 자료와 대조

이번 프로젝트는 사람이 고른 공개 발췌를 입력하는 활동. **검색 단계가 없으므로 RAG를 구현한 결과물은 아님**. RAG와 비교하면 '자료를 입력에 함께 넣는 단계'를 경험하는 자리.

- 자료 연결과 가중치 학습은 서로 다른 과정
- 검색한 자료가 오래되거나 질문과 무관하면 답의 근거도 약해지는 가능성
- 자료를 넣었더라도 모델이 내용을 빠뜨리거나 잘못 연결할 가능성
- 검색 시스템 구축·검색 모델 학습·구현 프레임워크는 이번 주 범위 밖

#### SFT와 RLHF: 이름과 목적만

| 이름 | 뜻과 목적 | 이번 주의 확인 범위 |
|---|---|---|
| SFT | 지도 미세조정. 지시와 바람직한 응답 예시로 응답 방식을 학습하는 과정 | 예시로 모델 가중치를 조정한다는 목적 |
| RLHF | 사람 피드백을 활용한 강화학습. 사람이 선호하는 응답 방향을 학습에 반영하는 접근 | 사람 선호를 반영한다는 목적 |

SFT에서 쓰는 학습 예시와 few-shot 입력 예시의 구분. 전자는 학습 단계에서 가중치 조정에 사용, 후자는 지금 요청의 문맥에 사용.

사람이 선호한 답도 사실과 다를 수 있는 가능성. 사람 피드백을 받았다는 이유로 출처 대조가 필요 없어지는 것은 아님. 학습 알고리즘과 자동 프롬프트 최적화 구현은 후속 과목 범위.

### 온라인 학습활동

- 공통 골격에서 목적·자료·제약·출력·근거에 해당하는 줄 표시
- A와 B의 차이를 '확인 불가 답변 형식 예시의 유무'로 한 문장 기록
- 두 발췌에서 답할 수 있는 질문과 답할 수 없는 질문 구분
- 상정 조직에서 프롬프트를 먼저 시험할 이유를 비교표의 비용·준비 항목으로 설명

## 대면 (1시수)

### 미니 프로젝트 수행 순서

1. [보고서·발표 기록 양식](/worksheets/week-12/mini-project-template.md) 다운로드
2. 11주차에서 실행한 공개 모델과 제공된 환경 확인
3. 같은 일반 모델·자료·질문·생성 설정을 고정하고 A 실행
4. 같은 조건에서 예시 한 개만 더한 B 실행
5. 공통 질문 세 개의 실제 결과를 원문 그대로 기록
6. 주장별 근거를 대조하고 결과의 차이·판단 보류 사항 정리
7. 보고서 작성 후 발표 표를 바탕으로 결과 공유

11주차의 일반 모델 실행 경로를 재사용하는 방식. 일반 모델과 추론형 모델까지 동시에 바꾸면 '프롬프트만 바꾼 비교'가 어려우므로 이 프로젝트에서는 한 모델로 고정.

- 동일 모델 ID·버전·생성 설정 기록
- 동일한 공개 발췌 두 개를 A와 B에 제공
- 질문마다 이전 대화를 포함하지 않는 새 입력 사용
- 출력 제한에 잘렸다면 잘림 상태도 함께 기록
- 환경·다운로드 문제로 실행되지 않은 항목은 **미실행** 표시. 예상 답을 실행 결과로 채우지 않는 원칙

### 제공된 실행 셀

11주차 노트북을 **먼저 끝까지 실행한 뒤**, 마지막에 새 코드 셀 하나를 추가하고 아래 제공 코드를 그대로 붙여 실행. 코드 작성·수정과 새 TODO 없음. 별도 12주차 노트북 파일 없이 기존 제공 함수와 일반 모델 설정을 재사용하는 방식.

```python
required = ("run_conditions", "GENERAL", "GENERAL_REVISION")
if not all(name in globals() for name in required):
    raise RuntimeError("11주차 노트북을 먼저 끝까지 실행한 뒤 이 셀 실행")

sources = (
    "[H] Hallasan. At 1,950 m above sea level, it is the highest mountain in South Korea.\n"
    "[O] Jeju Olle Trail Route 6 is an 11-kilometer coastal and urban trail.\n"
)
common = (
    "Purpose: Answer a visitor's question using only the supplied sources.\n"
    "Sources:\n" + sources +
    "Rules: Do not add facts absent from the sources.\n"
    'If the sources do not answer the question, write "Not stated".\n'
    "Format: Answer | Source ID | Evidence\n"
)
example = (
    "Example:\n"
    "Question: What is the admission fee for Hallasan?\n"
    "Answer: Not stated | None | The supplied sources do not state a fee.\n"
)
questions = [
    "How high is Hallasan above sea level?",
    "How long is Jeju Olle Trail Route 6?",
    "How many hours does it take to walk Route 6?",
]
conditions = {}
for index, question in enumerate(questions, start=1):
    for label, extra in (("A", ""), ("B", example)):
        prompt = common + extra + "Question: " + question + "\nAnswer:"
        conditions[f"{label}{index}"] = [{"role": "user", "content": prompt}]
project_results = run_conditions(GENERAL, GENERAL_REVISION, conditions)
for label, result in project_results.items():
    print(label, result)
```

- `A1/B1`, `A2/B2`, `A3/B3`: 질문 번호별 zero-shot·few-shot 실제 실행 결과
- 11주차의 일반 모델과 고정 버전·CPU·동일 생성 설정 사용. 6개 조건을 한 모델에서 순서대로 실행
- `status: ok`: 실제 출력의 `raw`·`answer`를 기록표로 옮긴 뒤 원문 대조
- `status: truncated`: 길이 제한에 도달한 불완전 출력으로 표시하고 잘린 출력도 그대로 기록
- `status: unavailable`: 오류와 미실행 상태 기록. 예상 답으로 대체 금지
- 이 셀은 공개 자료를 손으로 제공하는 비교 실험. 검색 시스템이나 RAG 구현 아님

### 실제 결과 기록표

| 질문 | A 실제 출력 | B 실제 출력 | 원문 근거 | 확인 상태 |
|---|---|---|---|---|
| 1: 한라산 높이 | 실행 후 기록 | 실행 후 기록 | H의 해당 표현 | 확인/불일치/확인 불가 |
| 2: 올레 거리 | 실행 후 기록 | 실행 후 기록 | O의 해당 표현 | 확인/불일치/확인 불가 |
| 3: 올레 소요시간 | 실행 후 기록 | 실행 후 기록 | 발췌에 없음 | 확인 불가 처리/추측 추가 |

- 출력의 Source ID만 믿지 않고 실제 원문 표현 확인
- 단위와 숫자가 함께 맞는지 대조
- 내용이 맞아도 지정 형식을 지키지 못한 경우 따로 기록
- 답이 같으면 차이 없음으로 기록. few-shot의 효과를 만들기 위해 결과를 수정하지 않는 기준

### 결과 비교와 해석

- **내용**: 답의 핵심 주장에 원문 근거가 있는지
- **형식**: 답변·출처 ID·근거 세 항목을 구분했는지
- **범위**: 자료에 없는 소요시간을 추가했는지
- **한계**: 작은 영어 공개 모델의 사례를 한국어 관광 서비스 전체 성능으로 일반화하지 않는 기준

세 질문의 작은 실험은 프롬프트 차이를 관찰하는 자료. 대표적인 실제 이용자 평가나 통계적 성능 검증과 구분. B가 나아 보이면 어떤 출력에서 어떤 항목이 달라졌는지 구체적으로 기술.

### 발표 표

| 설명할 항목 | 발표에 담을 내용 |
|---|---|
| 목적과 자료 | 방문자 질문, 공개 자료 URL·열람일·가공 |
| 고정한 조건 | 모델·버전·질문·생성 설정 |
| 바꾼 부분 | A와 B 프롬프트, 예시 추가 위치 |
| 관찰한 결과 | 실제 출력 두 개 이상을 근거와 함께 비교 |
| 확인하지 못한 점 | 자료에 없는 정보, 실행 문제, 적용 범위 |
| 다음 선택 | 프롬프트 개선 또는 추가 평가가 필요한 이유 |

- Q6. 사람이 고른 자료를 입력한 이번 활동과 RAG의 검색 단계 차이 설명

## 자주 묻는 질문

### 예시를 넣으면 언제나 답이 좋아지는가

항상 개선된다는 보장 없음. 예시가 형식을 알려 주더라도 모델이 따르지 않거나 본문을 반복할 가능성. 이번 실험의 실제 출력으로 확인할 항목.

### 자료에 없는 내용을 모델이 알고 있으면 써도 되는가

이번 비교 과제의 기준은 **제공 자료로 확인 가능한 답**. 자료 밖의 주장은 이 과제에서 확인 불가로 기록. 최신 이용 정보가 필요하면 공식 원문을 추가 확인한 뒤 별도 실험으로 구분.

### 다운로드한 양식은 새 실습 노트북인가

보고서와 발표 기록용 Markdown 파일. 실행 코드나 새 노트북이 아니며, 11주차 제공 환경에서 얻은 실제 결과를 적는 양식.

### 작은 모델이 지시를 따르지 못하면 실패한 과제인가

지시 불이행도 관찰 결과. 실제 출력과 환경을 남기고 무엇을 확인하지 못했는지 설명하는 활동. 정상 실행이 되지 않은 경우에는 결과를 만들지 않고 미실행 상태 기록.
