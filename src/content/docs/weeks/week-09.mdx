## 이번 주차

시퀀스 모델링과 트랜스포머의 등장.

□ 이번 주에 하는 일

- 단어를 차례로 읽는 **RNN·LSTM**이 앞의 정보를 뒤로 전달하는 방법과 한계 관찰
- 현재 단어가 다른 위치를 얼마나 참고하는지 나타내는 **어텐션**의 행 하나 읽기
- **트랜스포머**의 구조를 수식 없이 따라가고, 제공 노트북에서 어텐션 그림과 빈칸 후보 비교

문장 뒤쪽에서 '그것'을 만나면 앞쪽을 다시 본다. 무엇을 가리키는지 알기 위해서다. 그림에서 떨어진 카드 사이에 선이 이어진 것도 같은 생각이다. 컴퓨터가 글을 읽을 때 앞의 정보를 어떻게 가져오는지가 이번 주의 질문이다.

□ 8주차에서 이어지는 자리

8주차에는 문장과 문서를 벡터로 바꾸어 질문에 맞는 문서를 찾았다. 문장 임베딩 모델이 단어들을 서로 견주며 읽는다고 설명했지만, 안에서 어떻게 읽는지는 아직 보지 않았다. 이번 주는 그 안으로 들어간다. 검색기를 새로 만드는 것이 아니라, **문맥을 반영하는 벡터가 만들어지는 경로**를 본다.

7주차에는 단어 하나에 벡터 하나가 있었다. `오름`의 화산 지형과 '값이 오름'의 뜻이 같은 벡터에 섞였다. 이번 주의 출발점은 여기다. 같은 글자라도 주변 말이 다르면 다른 표현이 필요하다. '은행에 입금했다'와 '은행 열매를 주웠다'의 은행을 주변 말 없이 구별할 수 있을까?

| 비교 | 7주차 단어 벡터 | 8주차 문장 임베딩 | 9주차에서 볼 것 |
|---|---|---|---|
| 표현 대상 | 단어 하나 | 문장 전체 | 문장 안의 각 위치 |
| 문맥 | 학습한 여러 문맥이 한 벡터에 섞임 | 입력 문맥을 반영한 문장 벡터 | 현재 입력의 다른 위치를 참고하는 과정 |
| 핵심 질문 | 어떤 단어와 가까운가 | 어떤 문서와 가까운가 | 지금 표현을 만들 때 어디를 참고하는가 |

□ 이 문서를 읽는 법

- 수식은 나오지 않는다. **구조와 출력 해석**이 목표이며 RNN·어텐션 코드를 직접 작성하지 않음
- 이론과 교육용 모형의 민지·우산 문장은 **설명용 예시**, 실제 공개 원문 아님
- 실제 모델 입력은 제주관광공사의 **Hallasan 공개 원문**에 제목을 붙이고 한 단어를 빈칸으로 바꾼 것, 출처는 강의 2에서 확인
- 실제 출력 표는 제공 노트북의 기본값 실행 결과. 가중치와 확률은 소수 셋째 자리로 반올림
- 모델은 공개 영어 모델 `prajjwal1/bert-tiny`(MIT), 한국어 이해 능력이나 제주 사실을 검증하는 도구 아님
- 노트북은 CPU만 사용. 기본값으로 끝까지 실행하며, TODO 입력 교체는 **선택 활동 한 지점**

## 온라인 (2시수)

### 강의 1: 차례로 읽는 모델과 긴 문장의 문제

□ 단어가 같아도 순서가 다르면

8주차의 단어 벡터 평균은 '안 먹고 잤다'와 '먹고 안 잤다'를 구별하지 못했다. 더하는 순서를 바꾸어도 평균은 같기 때문이다. 하지만 앞 문장은 밥을 먹지 않고 잤다는 뜻이고, 뒤 문장은 먹은 다음 잠을 자지 않았다는 뜻이다. `안`이 어느 말 앞에 놓이는지가 결론을 바꾼다.

문장을 단어 모음이 아니라 **순서가 있는 목록**, 즉 **시퀀스**로 다루면 이 문제를 줄일 수 있다. 모델이 첫 토큰을 읽은 다음 둘째를 읽고, 앞서 본 내용을 다음 단계에 가져가는 것이다. 사람이 읽는 방식과 닮았지만, 컴퓨터가 가져가는 것은 원문을 담은 메모가 아니라 숫자 목록이다.

□ RNN: 앞에서 받은 정보를 다음으로

**RNN(순환 신경망)**은 토큰을 하나씩 읽으면서 **상태**를 갱신한다. 상태는 지금까지 읽은 정보를 담도록 학습되는 벡터다. 현재 토큰과 이전 상태를 함께 넣으면 새 상태가 나온다. 새 상태를 다음 위치로 넘겨 같은 일을 반복한다.

<img src={relayState.src} alt="제주 돌담 교실에서 학생 세 명이 주황색 카드가 든 작은 바구니를 차례로 건네는 그림. 각 학생 앞에는 빈 카드 몇 장이 놓여 있다" loading="lazy" decoding="async" style="max-width: 100%; border-radius: 8px; margin: 1rem 0;" />

그림은 실제 모델 구조도가 아니라 **현재 상태를 다음 위치로 전달하는 릴레이의 비유**다. 여러 사람이 쪽지를 건네며 각자 새 정보를 적는다고 생각하자. 뒤의 사람은 처음 사람을 직접 만나지 않고, 앞 사람이 건네준 쪽지에서 시작한다. RNN도 각 위치에서 이전 상태를 받아 현재 입력과 섞어 새 상태를 만든다. 다만 **쪽지에 모든 원문을 그대로 적을 수 있는 것은 아니다.** 상태의 크기는 정해져 있어 무엇을 남길지 학습해야 한다.

노트북의 교육용 모형과 같은 설명용 문장으로 따라가 보자. '민지는 제주에서 우산을 샀다. 그것은 빨갛다.'이다. 아래 표는 모델을 실행해 측정한 내용이 아니라, 정보 전달 경로를 설명하는 표다.

| 읽는 위치 | 지금 들어오는 말 | 다음 위치에 남겨야 할 정보의 예 |
|---|---|---|
| 1 | 민지는 | 행동하는 사람 |
| 2 | 제주에서 | 행동이 일어나는 장소 |
| 3 | 우산을 | 행동의 대상 |
| 4 | 샀다 | 앞의 사람·장소·대상이 구매 사건이라는 연결 |
| 5 | 그것은 | 앞의 대상과 현재 대명사를 연결할 정보 |
| 6 | 빨갛다 | 그 대상의 속성 |

표의 '남겨야 할 정보'는 사람의 해설이다. 상태 벡터 안에 '사람 칸', '장소 칸', '우산 칸'이 이름표를 달고 있는 것은 아니다. 7주차 밀집 벡터처럼 여러 칸의 숫자가 함께 표현한다. 이 차이를 기억해야 상태를 사람이 쓴 요약문처럼 읽는 오해를 피할 수 있다.

<FigureFrame src="/interactive/week-09/sequence-context.html" title="RNN의 차례로 읽기와 어텐션의 참조 위치" height="430px" />

그림의 **RNN: 차례로 읽기**를 고르고 '다음 토큰'을 누른다. 강조 표시가 왼쪽에서 오른쪽으로 움직인다. '우산을'에서 생긴 정보가 '샀다'를 지나 '그것은'에 전달되어야 한다는 점을 본다. **어텐션: 참고 위치 보기**로 바꾸면 떨어진 두 위치가 함께 강조된다. 실제 모델 가중치가 아니라, 두 정보 전달 방식의 차이를 보여 주는 도식이다.

□ 길어질 때 어려워지는 이유

우산 뒤에 '돌담 옆을 걷고, 친구를 만나고, 다른 가게를 구경한 뒤' 같은 내용을 넣는다고 하자. 이것도 구조를 설명하기 위해 만든 문장이다. '그것은'에 도착할 때까지 다른 정보가 계속 들어오고 상태가 여러 번 바뀐다. 우산의 정보가 뒤의 표현을 만드는 데 필요하더라도 그 정보가 충분히 유지된다는 보장은 없다.

어려움은 두 가지로 나눌 수 있다. 첫째, **정해진 크기의 상태에 많은 정보를 남겨야 한다.** 둘째, 앞의 정보가 뒤까지 **여러 갱신 단계를 거쳐야 한다.** 학습할 때도 멀리 떨어진 관계를 반영하려면 그 경로를 따라 숫자를 고쳐야 하므로 어려울 수 있다. 이번 주는 이 학습 과정의 공식까지 들어가지 않는다.

- '길면 반드시 잊는다'는 고정 법칙이 아니라, 길고 복잡한 관계를 유지하기 어려울 수 있다는 설명
- 어느 단어 수부터 실패한다는 보편적인 경계는 없음, 문장·설정·학습에 따라 다른 결과
- 순차 처리에서는 뒤 단계가 앞의 상태를 기다려야 하므로, 여러 위치를 동시에 처리하는 데 제약

□ LSTM: 남길 정보와 지울 정보 조절

**LSTM**은 RNN 계열이지만 정보를 남기고 지우는 조절 장치를 둔다. 지금 입력에서 무엇을 새로 받아들일지, 이전 정보 중 무엇을 유지할지, 현재 위치에서 무엇을 밖으로 내보낼지 조절한다. 이런 장치를 흔히 **게이트**, 문이라고 부른다.

쪽지 비유로 보면 새 사건을 적을 때마다 이전 쪽지를 통째로 바꾸는 대신, 오래 남길 부분과 당장 쓸 부분을 나누어 관리하는 것이다. '우산을 샀다'의 대상은 뒤에서 다시 쓸 수 있으니 유지하고, 잠깐 지나가는 정보는 덜 남길 수 있다. 그러나 모델이 실제로 그렇게 남겼는지는 별도의 관찰이 필요하다. 이 예시는 설계의 직관이며 우산을 기억한 실험 결과가 아니다.

| 질문 | RNN | LSTM |
|---|---|---|
| 새 상태는 무엇에서 나오나 | 이전 상태와 현재 입력 | 이전 상태·기억과 현재 입력, 조절 게이트 |
| 앞의 정보를 어떻게 보존하나 | 상태를 계속 갱신하며 전달 | 유지·삭제·출력을 조절하며 전달 |
| 긴 관계는 해결되나 | 여러 단계를 거치는 전달의 어려움 | 정보 유지에 도움, 완전한 보존 보장은 없음 |
| 뒤 위치는 앞 위치를 기다리나 | 기본 처리에서 필요 | 기본 처리에서 필요 |

LSTM을 '기억력이 좋은 RNN'이라고 요약해도 방향은 맞다. 더 정확히는 **기억을 조절하는 구조를 넣은 RNN**이다. 사람의 기억과 같은 기능을 가진다는 뜻은 아니다. 긴 관계를 다루는 데 도움이 되지만 모든 조건을 정확히 유지하거나 모호한 대명사를 자동으로 해결하지는 않는다.

□ 모호함은 기억만으로 풀리지 않는다

'민지는 우산을 샀다. 수진은 가방을 들었다. 그것은 빨갛다.'를 읽으면 무엇이 빨간지 확정하기 어렵다. 앞의 정보를 전부 기억해도 우산과 가방이 모두 후보로 남는다. '그것'을 '우산'으로 바꾸면 명확해진다. 이는 정보를 전달하는 능력과 원문 자체의 모호함이 다른 문제라는 뜻이다.

모델이 특정 대상을 골랐다고 해서 원문에 유일한 정답이 생기지는 않는다. 온라인 활동에서는 **확실한 참조와 가능한 해석을 나누어** 표시한다. 하나를 억지로 고르는 것보다 불확실한 이유를 설명하는 편이 정확하다.

□ 긴 안내문에서 무엇을 놓칠까

제주 행정·정책 안내에는 대상, 신청 기간, 지원 내용, 제외 조건이 떨어져 있을 수 있다. 처음의 대상 조건만 읽으면 가능해 보이지만, 마지막의 제외 조건이 판단을 뒤집을 수 있다. 내용이 길다는 것뿐 아니라 **여러 곳의 조건을 함께 충족해야 한다는 구조**가 어렵다.

실제 운영 정보를 임의로 만들지 않기 위해 여기서는 숫자와 기한을 제시하지 않는다. 실무 활동에서는 [공개 데이터 출처](/reference/data/)의 공식 안내문에서 대상·기한·예외 위치를 찾아 표시한다. 실제 자격 판단이나 신청을 대신하는 활동은 아니다.

| 읽기에서 필요한 것 | 놓쳤을 때 생기는 문제 | 확인 방법 |
|---|---|---|
| 대상 조건 | 지원 대상이 아닌 사람에게 가능하다고 안내 | 대상 문장과 정의를 함께 확인 |
| 기간 | 예전 일정이나 다른 절차의 기한을 혼동 | 날짜가 어느 절차에 붙었는지 확인 |
| 예외 조건 | 기본 대상이라도 제외되는 경우 누락 | 뒤쪽 단서·각주까지 확인 |
| 대명사·지시어 | '해당 대상'이 어느 조건을 가리키는지 혼동 | 앞 문장의 참조 범위 확인 |

□ 강의 1에서 꼭 가져갈 것

1. 시퀀스는 **순서가 있는 토큰 목록**이다. 같은 단어라도 순서가 달라지면 뜻이 바뀐다
2. RNN은 이전 상태와 현재 토큰을 함께 보고 **새 상태를 다음 위치로 전달**한다
3. 상태는 원문 복사본이 아니라 정해진 크기의 벡터다. 긴 관계는 여러 갱신 단계를 거쳐 전달된다
4. LSTM은 유지·삭제·출력을 조절하는 구조로 정보 유지에 도움을 주지만, 모든 관계의 보존을 보장하지 않는다
5. 원문이 모호하면 기억이 충분해도 답이 하나로 정해지지 않는다. 불확실한 참조는 불확실하다고 기록한다

### 강의 2: 참고 비중으로 문맥을 만드는 어텐션

□ 앞사람의 쪽지만 기다리지 않고

RNN의 경로가 길어지는 문제를 줄이려면 현재 위치에서 필요한 앞의 위치를 더 직접 참고할 수 있으면 좋다. '그것은'을 처리할 때 여러 상태를 거친 정보만 받는 대신, '우산을' 위치의 표현을 참고하는 것이다. **어텐션**은 어느 위치를 얼마나 참고할지 계산하고 그 비중으로 정보를 모으는 방식이다.

직관적으로 **'중요한 단어에 집중한다'**고 설명해도 좋다. 다만 여기의 중요함은 사람이 정답을 알고 매긴 점수가 아니다. 모델이 학습한 숫자로 현재 입력의 위치들을 견주어 얻은 **참고 비중**이다. 단어의 사전적인 중요성이나 사실이 맞을 확률과도 다르다.

□ 가중치 행 하나를 읽는 방법

노트북 1-1의 교육용 모형을 먼저 읽자. 토큰은 '민지는, 제주에서, 우산을, 샀다, 그것은, 빨갛다' 여섯 개다. 사람이 '그것은'의 행에 아래 비중을 직접 넣었다. 실제 모델에서 뽑은 값이 아니며 학습도 하지 않았다.

| 현재 위치 | 민지는 | 제주에서 | 우산을 | 샀다 | 그것은 | 빨갛다 |
|---|---|---|---|---|---|---|
| 그것은 | 0.05 | 0.05 | **0.70** | 0.05 | 0.10 | 0.05 |

행은 **표현을 만드는 현재 토큰**, 열은 **참고할 토큰**이다. 우산을의 칸 0.70은 이 행의 정보 결합에서 우산 위치에 큰 비중을 준다는 뜻이다. '우산이 정답일 확률 70%'라는 뜻은 아니다. 한 행의 비중을 모두 합하면 1이다. 계산은 코드가 하며 학생은 칸의 위치와 크기를 읽는다.

다른 행을 읽을 때는 현재 토큰이 달라진다. '그것은' 행에서 우산을 칸이 크다고 해서 '우산을' 행에서도 그것은 칸이 크다는 보장은 없다. **현재 위치에서 참고 위치로 향하는 관계**이므로 두 칸이 대칭일 필요가 없다. 6주차 동시발생 행렬이 좌우 대칭이었던 것과 다른 점이다.

<FigureFrame src="/interactive/week-09/attention-heads.html" title="교육용 헤드에 따라 다른 참고 비중" height="440px" />

그림에서 A, B, C를 차례로 고른다. A는 우산 위치에 큰 비중, B는 가까운 위치에 큰 비중, C는 고른 비중이다. 모두 사람이 지정한 값이다. 같은 입력에서도 **참고 비중의 모양은 여러 가지일 수 있다**는 구조만 보여 준다. 실제 모델의 헤드를 재현한 그림으로 읽지 않는다.

□ 자기 어텐션과 여러 헤드

같은 입력 안의 위치끼리 참고하는 어텐션을 **자기 어텐션**이라고 한다. 현재 위치의 벡터로 다른 위치와의 연결을 계산하고, 그 위치들의 정보를 가중치에 따라 모은다. 연결을 따지는 표현과 모을 정보를 만드는 표현이 내부에서 구분되지만, 이번 주는 수식이나 행렬 곱까지 들어가지 않는다.

**여러 헤드**는 이 참고 비중 계산을 서로 다른 방식으로 나란히 수행한다. 한 헤드는 가까운 위치를, 다른 헤드는 멀리 있는 위치를 자주 참고할 수 있다. 하지만 '첫 헤드는 주어 담당, 둘째는 대명사 담당'처럼 역할을 미리 정해 두는 것은 아니다. 같은 헤드도 입력에 따라 다른 패턴을 보일 수 있다.

헤드들의 결과를 모은 뒤 다음 변환으로 넘긴다. 따라서 헤드 하나의 큰 가중치만 읽으면 모델 전체가 참고한 정보의 일부만 본 것이다. **층과 헤드를 지정하고 어느 부분을 관찰했는지 기록하는 이유**가 여기에 있다.

□ 트랜스포머: 이 과정을 블록으로 반복

**트랜스포머**는 자기 어텐션을 중심으로 한 블록을 반복하여 문맥을 반영하는 구조다. 토큰마다 벡터가 있고, 한 층에서 다른 위치를 참고해 새 벡터를 만든다. 그 결과를 다음 층에 넘겨 다시 처리한다. RNN처럼 앞 위치의 새 상태가 나올 때까지 각 뒤 위치가 차례로 기다리는 흐름과 다르다.

한 층에서 여러 위치를 함께 계산할 수 있다는 말은 계산이 사라진다는 뜻이 아니다. 위치끼리 얼마나 참고할지 따지고, 그 정보를 결합하고 변환하는 일을 한다. 구조가 바뀌어도 단어를 숫자 목록으로 표현한다는 6~8주차의 바닥은 같다.

<FigureFrame src="/interactive/week-09/transformer-block.html" title="트랜스포머 인코더 블록의 정보 흐름" height="440px" />

선택 상자를 1부터 5까지 옮기며 순서를 따라간다. 이 그림은 노트북의 **인코더 블록 개념도**다. 처음 입력에서 마지막 출력까지 다음 역할을 구분하면 된다.

| 구성 | 하는 일 | 이 단계에서 묻는 질문 |
|---|---|---|
| 토큰 벡터와 위치 정보 | 내용과 순서를 함께 표현 | 어떤 조각이 어디에 있는가 |
| 여러 헤드의 자기 어텐션 | 다른 위치의 정보를 참고 비중으로 결합 | 다른 위치를 얼마나 참고할까 |
| 연결과 정규화 | 입력의 전달 경로 유지, 값의 크기 조절 | 이전 정보가 다음 계산에도 전달되는가 |
| 피드포워드 신경망 | 각 위치에서 같은 신경망으로 벡터 변환 | 모은 정보를 어떻게 새 표현으로 바꿀까 |
| 연결·정규화와 블록 반복 | 변환 결과를 다음 층으로 전달 | 다음 층에서 무엇을 다시 참고할까 |

피드포워드 단계는 위치마다 같은 변환을 적용한다. **위치끼리 정보를 섞는 역할은 앞의 어텐션 단계**다. 연결은 원래 입력을 더하는 경로이며, 정규화는 계산에 들어가는 값의 크기를 조절하는 과정이다. 이름을 암기하기보다 '참고하기, 위치별 변환, 정보 전달'이라는 역할을 먼저 구별한다.

□ 함께 읽더라도 어순은 필요하다

토큰을 함께 처리하면 '안 먹고 잤다'와 '먹고 안 잤다'의 차이가 다시 사라지는 것은 아닐까? 그래서 토큰 벡터에 **위치 정보**를 함께 넣는다. 어떤 토큰인지만이 아니라 입력에서 어디에 놓였는지도 모델이 사용할 수 있게 한다.

그림은 실제 모델의 위치 정보 계산을 그린 것이 아니라 **같은 카드의 어순이 달라지는 상황의 비유**다. 카드의 색이 내용이라면 놓인 자리는 위치다. 같은 카드가 모두 있다고 해도 어느 카드 앞뒤에 놓였는지에 따라 읽는 내용이 달라진다. 위치 정보를 넣는 방식은 모델마다 다르지만, 이번 주는 **병렬로 처리한다는 것과 순서를 버린다는 것은 다르다**는 점을 가져간다.

□ 인코더와 디코더가 보는 방향

노트북의 BERT 계열 모델은 **인코더**다. 빈칸 앞뒤를 모두 참고할 수 있다. 'the [MASK] mountain'에서 빈칸 뒤의 mountain도 후보를 고르는 단서가 된다. 뒤의 답을 미리 몰래 읽는 것이 아니라, 앞뒤 문맥의 빈칸을 맞히도록 만들어진 작업이다.

다음 토큰을 생성하는 **디코더**의 자기 어텐션에는 뒤 위치를 가리는 **인과적 마스크**가 들어간다. 앞의 입력으로 다음을 예측하는 동안 아직 나오지 않은 뒤의 말을 참고하면 안 되기 때문이다. 다만 추론 시 토큰을 하나씩 생성하는 과정에는 여전히 앞선 결과에 의존하는 순서가 있다. 트랜스포머의 한 층 계산을 병렬화하는 것과 생성 토큰 전체를 한 번에 확정하는 것은 다르다.

| 비교 | 인코더의 빈칸 채우기 | 디코더의 다음 토큰 예측 |
|---|---|---|
| 현재 작업 | 가린 위치의 토큰 맞히기 | 앞에서 이어질 다음 토큰 맞히기 |
| 참고 가능한 위치 | 빈칸 앞과 뒤 | 현재까지의 앞쪽 위치 |
| 뒤를 가리는 이유 | 해당 방식에서는 앞뒤 문맥 사용 | 아직 생성되지 않은 답을 보지 않기 위해 |
| 이번 주 실행 | BERT 계열 작은 모델 | 구조 차이만 설명, 생성 실습은 하지 않음 |

같은 '마스크'라도 두 용도를 구분한다. `[MASK]`는 **입력 문장에 넣는 빈칸 토큰**이다. 인과적 마스크는 **어텐션에서 참고를 금지하는 위치 표시**다. 노트북 문장에 `[MASK]`를 넣었다고 디코더처럼 뒤의 토큰을 가리는 것은 아니다.

□ 공개 원문으로 실제 모델 보기

실제 입력의 출처는 제주관광공사 [Hallasan 페이지](https://www.visitjeju.net/en/detail/view?contentsid=CONT_000000000500685), 열람일 2026-10-11이다. 원문 짧은 발췌는 'At 1,950 m above sea level, it is the highest mountain in South Korea.'이다. 페이지 제목 `Hallasan.`을 앞에 붙이고 한 단어를 `[MASK]`로 치환한다.

- 기본 입력 1: `Hallasan. At 1,950 m above sea level, it is the [MASK] mountain in South Korea.`
- 기본 입력 2: `Hallasan. At 1,950 m above sea level, it is the highest [MASK] in South Korea.`

사람은 `it`이 한라산을 가리킨다고 읽는다. 작은 모델의 마지막 층 첫 헤드도 한라산을 가장 많이 참고할까? 기본 입력 1의 실제 출력은 다음과 같았다. 이 표는 교육용 가중치와 달리 **사전학습 모델에서 계산한 값**이다.

| `it`의 참고 비중 순위 | 위치 번호 | 토큰 | 가중치 |
|---|---|---|---|
| 1 | 0 | `[CLS]` | **0.768** |
| 2 | 12 | `level` | 0.101 |
| 3 | 13 | `,` | 0.068 |
| 4 | 14 | `it` | 0.037 |
| 5 | 15 | `is` | 0.007 |

한라산이 아니라 **`[CLS]`가 맨 위**다. `[CLS]`는 입력 앞에 넣는 특수 토큰이지 산 이름이 아니다. 그렇다고 이 표만으로 '모델은 한라산을 전혀 참고하지 않는다'고 단정할 수도 없다. 앞 층과 다른 헤드, 여러 변환을 거친 결과를 보기 때문이다. 이번에 관찰한 것은 마지막 층 첫 헤드의 `it` 행 한 줄이다.

이 결과가 실습의 핵심이다. 교육용 모형에서는 원하는 참조를 사람이 넣었으므로 우산 위치가 크게 나온다. 실제 모델에는 그런 정답 그림을 넣지 않았다. **사람이 기대한 참조와 실제로 출력된 참고 비중을 비교하고, 일치하지 않는 부분을 정확히 기록**한다.

□ 빈칸 후보는 사실 검증 결과가 아니다

기본 입력 두 개의 빈칸 후보도 비교해 보자. 아래 값은 전체 어휘 분포에서 해당 후보에 준 확률이다. 다섯 후보만 보여 주므로 표의 확률을 합쳐도 1이 될 필요는 없다.

| 순위 | `highest`를 가린 입력 | 확률 | `mountain`을 가린 입력 | 확률 |
|---|---|---|---|---|
| 1 | `largest` | 0.159 | `peak` | 0.474 |
| 2 | `highest` | 0.109 | `level` | 0.141 |
| 3 | `tallest` | 0.044 | `point` | 0.079 |
| 4 | `oldest` | 0.035 | `altitude` | 0.040 |
| 5 | `mountain` | 0.030 | `elevation` | 0.037 |

첫 입력의 원래 단어 highest는 1위가 아니라 2위다. 둘째의 원래 단어 mountain은 상위 다섯 개에 없다. 앞뒤 문맥을 참고한다고 해서 원문 단어를 항상 복원하지는 않는다. 작은 영어 모델이 그 입력에서 학습한 패턴에 따라 제안한 결과다.

표에서 읽을 것은 '한라산이 실제로 무엇인지'가 아니라 **빈칸 위치에 따라 후보의 종류가 바뀌는지**다. the와 mountain 사이를 가리면 크기·높이와 관련된 말이 여러 개 나오고, highest 뒤를 가리면 peak 같은 명사가 나온다. 일부 후보는 어색하다. 자연스러운 후보와 원문과 다른 후보를 함께 기록해야 모델의 한계가 보인다.

□ 긴 문서는 어텐션만으로 끝나지 않는다

어텐션은 떨어진 위치를 참고하는 경로를 만들지만, 모든 관계를 정확히 찾아주는 장치가 아니다. 기본적인 전체 자기 어텐션은 토큰 위치 간 조합을 계산한다. 입력 길이가 늘면 비교할 조합이 빠르게 늘어 계산·메모리 부담이 커진다. 문서를 무한히 넣을 수 있는 것도 아니다.

이번 노트북은 입력을 최대 64토큰으로 제한한다. 길이가 넘으면 뒤가 잘릴 수 있고, 잘린 뒤에 빈칸이 없어졌는지도 확인한다. 모델이 볼 수 있는 범위 안의 내용만 관찰한 것인지, 필요한 조건이 잘려서 보이지 않았는지를 구분해야 한다. 들어온 조건을 놓치는 문제와 **아예 입력되지 않은 조건**은 원인이 다르다.

□ 강의 2에서 꼭 가져갈 것

1. 어텐션은 다른 위치의 정보를 **참고 비중에 따라 모으는 방식**, 큰 가중치는 정답·사실 확률이 아님
2. 자기 어텐션은 같은 입력 안의 위치끼리 참고한다. 여러 헤드는 별도의 비중을 계산하지만 역할이 고정된 것은 아님
3. 트랜스포머는 참고하기와 위치별 변환을 블록으로 반복한다. **위치 정보**를 넣으므로 함께 처리해도 어순 구별 가능
4. 인코더는 앞뒤 빈칸 문맥을, 다음 토큰을 예측하는 디코더는 앞쪽 문맥을 사용. 빈칸 토큰과 인과적 마스크 구분
5. 실제 `it` 행의 1위는 `[CLS]` 0.768이었다. 한 헤드의 비중을 모델 전체의 이해나 원인으로 단정하지 않기
6. 빈칸 위치가 바뀌면 후보도 바뀐다. 후보 확률은 원문 복원·사실 검증 성공률이 아님

## 자주 하는 오해 Q&A

<details>
<summary>Q1. RNN의 상태는 앞 문장 전체를 저장한 메모인가?</summary>

아니다. 상태는 **정해진 크기의 벡터**다. 앞서 들어온 토큰과 상태를 함께 계산해 새 상태를 만든다. 원문을 그대로 복사해 두는 것이 아니며, 칸마다 '사람', '장소' 같은 고정 이름이 붙어 있지도 않다. 긴 문장에서 필요한 정보를 남기는 일이 어려울 수 있다는 이유가 여기에 있다.

</details>

<details>
<summary>Q2. LSTM은 기억을 유지하니 긴 문서도 정확히 읽는가?</summary>

그렇게 보장하지 않는다. LSTM은 무엇을 유지하고 지울지 조절하는 구조로 **긴 관계의 정보 전달을 돕는다.** 하지만 정해진 크기의 표현을 쓰고 기본 처리에서 앞 단계에 의존한다. 원문에 모호한 대명사가 있으면 앞을 모두 기억해도 답이 하나로 정해지지 않는다. 구조의 도움과 모든 문서의 정확한 이해를 구분한다.

</details>

<details>
<summary>Q3. 어텐션 0.70이면 그 단어가 정답일 확률 70%인가?</summary>

아니다. 그 값은 **현재 행에서 해당 위치를 참고하는 비중**이다. 교육용 모형의 그것은 행에서 우산에 0.70을 넣은 것은 참고 정보를 그렇게 모으도록 사람이 정한 것이다. 대명사의 정답 확률을 학습한 결과가 아니다. 빈칸 후보의 확률은 다른 출력에서 나오며, 그 확률도 실제 사실의 참·거짓 확률은 아니다.

</details>

<details>
<summary>Q4. 실제 어텐션에서 한라산 대신 [CLS]가 크면 모델이 아무것도 이해하지 못한 것인가?</summary>

그 행 하나로 모델 전체를 판정할 수 없다. 이번에는 **마지막 층 첫 헤드의 it 행**을 보았다. 앞 층과 다른 헤드, 위치별 변환을 거친 정보도 결과에 들어간다. `[CLS]`가 크다는 관찰은 기록하되, '한라산은 전혀 쓰지 않았다' 또는 '특수 토큰이 답의 원인이다'라는 결론으로 바로 넘어가지 않는다. 가중치 관찰과 내부 원인 증명은 다르다.

</details>

<details>
<summary>Q5. 여러 헤드는 각각 주어·목적어·대명사를 맡는가?</summary>

역할을 그렇게 고정해 두지 않는다. 헤드들은 **서로 다른 참고 비중을 학습**한다. 어떤 입력에서 문법 관계처럼 보이는 패턴이 나타나더라도 그 헤드가 모든 문장에서 같은 역할만 맡는다는 뜻은 아니다. 교육용 A·B·C는 차이를 보기 위해 사람이 지정한 예시이며 실제 모델의 역할표가 아니다.

</details>

<details>
<summary>Q6. 트랜스포머는 함께 계산하므로 단어 순서를 무시하는가?</summary>

아니다. 토큰 벡터에 **위치 정보**를 함께 사용한다. '안 먹고 잤다'와 '먹고 안 잤다'가 다른 순서임을 계산에 반영할 수 있다. 한 층에서 여러 위치를 함께 처리하는 것과 순서를 버리는 것은 다르다. 디코더가 새 토큰을 하나씩 생성할 때는 다음 입력이 이전 생성 결과에 의존한다는 점도 구분한다.

</details>

<details>
<summary>Q7. [MASK]를 넣으면 모델이 뒤 문장을 못 보게 되는가?</summary>

아니다. 이번 인코더에서 `[MASK]`는 **가린 단어의 자리**이고, 그 앞뒤 문맥을 참고해 후보를 만든다. 뒤 위치를 보지 못하게 하는 인과적 마스크는 다음 토큰 예측의 어텐션에 적용하는 다른 장치다. 문장의 빈칸 표시와 참고를 금지하는 위치 표시를 같은 뜻으로 읽지 않는다.

</details>

<details>
<summary>Q8. 빈칸 1위가 largest면 공식 원문의 highest가 틀린 것인가?</summary>

아니다. 모델의 후보는 **그 입력에서 학습된 패턴으로 계산한 제안**이다. 한라산의 실제 설명이 맞는지 확인하려면 공식 원문을 읽어야 한다. 작은 모델이 highest를 2위로 둔 것을 사실의 우열로 읽으면 안 된다. 둘째 입력의 원래 단어 mountain이 상위 다섯 후보에 없었다는 한계도 함께 남긴다.

</details>

## 이번 주 용어 정리

| 용어 | 한 줄 뜻 |
|---|---|
| 시퀀스 | 순서가 있는 토큰 목록 |
| 상태 | 앞서 읽은 정보를 다음 위치로 전달하는 벡터 |
| RNN | 이전 상태와 현재 입력으로 새 상태를 만드는 순환 신경망 |
| LSTM | 정보를 유지·삭제·출력하도록 조절하는 RNN 계열 |
| 게이트 | 정보를 얼마나 남기거나 내보낼지 조절하는 장치 |
| 어텐션 | 다른 위치를 참고할 비중을 계산하고 그 정보들을 결합하는 방식 |
| 자기 어텐션 | 같은 입력 안의 위치끼리 참고하는 어텐션 |
| 헤드 | 별도의 참고 비중을 계산하는 단위, 역할이 사전에 고정된 것은 아님 |
| 위치 정보 | 토큰의 위치와 순서를 계산에 반영하는 정보 |
| 트랜스포머 | 자기 어텐션과 위치별 변환 등을 블록으로 반복하는 구조 |
| 피드포워드 | 각 위치에서 같은 신경망으로 표현을 변환하는 단계 |
| 인코더 | 이번 실습에서 앞뒤 문맥을 참고하는 표현 구조 |
| 디코더 | 다음 토큰 예측에서 앞쪽만 참고하도록 가리는 구조 |
| 빈칸 토큰 | 입력에서 가린 단어의 위치를 표시하는 `[MASK]` |
| 인과적 마스크 | 아직 나오지 않은 뒤쪽 위치의 참고를 금지하는 표시 |
| WordPiece 조각 | 단어를 여러 조각으로 나눈 토큰, `##`는 앞 조각에 이어지는 표시 |
