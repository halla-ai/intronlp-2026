## 온라인 (2시수)

### 강의 1: 순서대로 읽는 모델과 긴 문장의 문제

**시퀀스**는 순서가 있는 목록이다. 문장은 순서가 있는 토큰 목록으로 볼 수 있다. '안 먹고 잤다'와 '먹고 안 잤다'는 단어가 같아도 뜻이 다르다. 단어 가방과 단어 벡터 평균은 이 차이를 잃기 쉽다.

**RNN(순환 신경망)**은 토큰을 하나씩 읽고, 이전까지의 정보가 담긴 **상태**를 다음 단계에 전달한다. 현재 토큰과 이전 상태를 함께 보고 새 상태를 만든다. 상태는 원문 전체의 복사본이 아니라 제한된 크기의 벡터다.

<FigureFrame src="/interactive/week-09/sequence-context.html" title="RNN의 차례로 읽기와 어텐션의 참조 위치" height="430px" />

'민지는 제주에서 우산을 샀다. 그것은 빨갛다.'를 보자. 사람이 '그것은'을 읽으면 앞의 '우산을'을 다시 본다. RNN에서는 우산의 정보가 여러 상태를 거쳐 그것의 위치까지 전달되어야 한다. 사이에 다른 내용이 늘어나면 필요한 정보를 유지하기 어려울 수 있다. 일정한 단어 수가 지나면 반드시 잊는다는 뜻은 아니다.

**LSTM**은 무엇을 남기고 지울지 조절하는 문을 두어 정보를 유지하도록 설계한 RNN 계열이다. 장거리 정보 전달을 돕지만, 긴 문서의 모든 관계를 완벽히 보존하는 장치는 아니다. 기본적인 토큰 처리도 앞선 단계의 상태에 의존한다.

| 비교 | RNN | LSTM |
|---|---|---|
| 기본 흐름 | 이전 상태와 현재 토큰으로 새 상태 생성 | 유지·삭제를 조절하며 상태 전달 |
| 긴 문장 | 여러 단계를 거치는 정보 전달의 어려움 | 정보 유지 개선, 모든 관계 보존 보장은 없음 |
| 처리 의존성 | 앞 단계의 상태에 의존 | 앞 단계의 상태에 의존 |

**긴 제주 행정 안내 읽기**에서도 같은 문제가 보인다. 첫 부분에 대상, 가운데에 신청 기간, 마지막에 제외 조건이 있다면 한 부분만 읽어서는 신청 가능 여부를 판단할 수 없다. 문서가 길다는 사실 외에도 조건이 떨어져 있고, 예외가 결론을 바꾼다는 점이 어렵다. 실습에서는 실제 신청 자격을 판정하지 않고 이 구조만 관찰한다.

- 긴 문장의 대명사: 무엇을 가리키는지 찾고, 참고해야 할 앞부분 표시
- 조건이 많은 문서: 대상·기한·예외를 각각 표시한 뒤 함께 읽기
- 모델의 결과: 빠뜨린 조건이 있는지 원문과 대조

### 강의 2: 어텐션과 트랜스포머

**어텐션**은 현재 위치의 표현을 만들 때 다른 위치를 얼마나 참고할지 가중치를 계산하고, 그 비중으로 정보를 모으는 방식이다. 직관적으로 '필요한 단어에 더 집중하기'라고 설명해도 좋다. 다만 실제 가중치는 사람이 고른 중요도나 정답 확률과 같지 않다.

'그것은'에서 '우산을'을 많이 참고한다면 사람이 고른 참조 관계와 닮아 보인다. 하지만 특수 토큰이나 자기 자신에 큰 비중이 나타날 수도 있다. 가장 큰 비중의 토큰 하나만으로 모델이 대명사를 정확히 이해했다고 결론 내릴 수 없다.

<FigureFrame src="/interactive/week-09/attention-heads.html" title="교육용 헤드에 따라 다른 참고 비중" height="440px" />

- 이 그림의 값: 학습 결과가 아닌 **사람이 지정한 교육용 가중치**
- 노트북의 실제 값: 사전학습 모델이 입력 문장을 받아 계산한 가중치
- 행: 현재 표현을 만드는 토큰, 열: 참고하는 토큰
- 한 행의 가중치 합: 1, 각 값은 그 행에서의 참고 비중

**자기 어텐션**은 같은 문장 안의 토큰끼리 참고하는 어텐션이다. **여러 헤드**는 서로 다른 가중치 계산을 나란히 수행한다. 헤드마다 '주어 담당', '대명사 담당'이라고 미리 정해 둔 것은 아니다. 관찰에서 그렇게 보이는 사례가 있어도 일반 규칙으로 단정하지 않는다.

**트랜스포머**는 자기 어텐션을 중심으로 여러 블록을 쌓아 문맥을 반영하는 구조다. 순서대로 상태를 넘기는 방식과 달리, 한 층에서 여러 위치의 표현을 함께 계산할 수 있다. 하지만 어순을 버려도 된다는 뜻은 아니다. 토큰 벡터에 **위치 정보**를 넣어 위치를 구별한다.

<FigureFrame src="/interactive/week-09/transformer-block.html" title="트랜스포머 인코더 블록의 정보 흐름" height="440px" />

| 구성 | 역할 |
|---|---|
| 토큰 벡터와 위치 정보 | 토큰의 내용과 순서 표현 |
| 여러 헤드의 자기 어텐션 | 다른 위치의 정보를 참고 비중에 따라 모으기 |
| 연결과 정규화 | 입력 정보의 전달 경로 유지, 값의 크기 조절 |
| 피드포워드 신경망 | 위치별 벡터 변환 |
| 블록 반복 | 문맥을 반영한 표현을 다음 층에서 다시 처리 |

노트북의 BERT 계열 모델은 빈칸 앞뒤를 참고하는 **인코더**다. 다음 토큰을 생성하는 **디코더**에서는 자기 어텐션이 뒤쪽 토큰을 보지 못하도록 가린다. 트랜스포머라고 해서 모두 같은 방향으로 읽는 것은 아니다.

빈칸 채우기는 인코더를 관찰하기 좋은 작업이다. 실제 모델 입력은 제주관광공사 공개 [Hallasan 페이지](https://www.visitjeju.net/en/detail/view?contentsid=CONT_000000000500685)(열람일 2026-10-11)의 짧은 원문을 사용한다. 원문 'At 1,950 m above sea level, it is the highest mountain in South Korea.' 앞에 페이지 제목 `Hallasan.`을 붙이고 `highest`를 `[MASK]`로 치환한다. `it`이 가리키는 한라산의 토큰 위치와 실제 참고 비중을 비교한다. 모델은 어휘 목록 전체에 후보별 값을 만든다. 실습은 후보 다섯 개와 그 확률을 출력한다. 그 확률은 **이 입력에서 모델이 빈칸에 줄 비중**이며, 실제 산의 높이·순위 등 제주 사실이 맞을 확률이 아니다. 작은 모델의 후보가 자연스럽지 않아도 관찰 대상으로 삼을 수 있다.

**어텐션도 긴 문서를 모두 해결하지는 않는다.** 기본적인 전체 자기 어텐션은 토큰 간 조합을 계산하므로 길이가 늘면 계산·메모리 부담이 커진다. 모델 입력 길이 제한으로 문서의 일부가 잘릴 수도 있고, 안에 들어온 조건도 놓칠 수 있다. 이번 노트북은 최대 64토큰으로 제한하고 잘린 뒤에 빈칸이 남아 있는지도 확인한다.

## 대면 (1시수)

### 제공 노트북 실행과 결과 읽기

- 기본값으로 위에서부터 전체 실행, 필수 코드 작성 없음
- 교육용 모형의 가중치 그림 먼저 관찰
- 작은 사전학습 모델을 CPU로 불러온 뒤 실제 가중치 관찰
- 마지막 층의 첫 헤드에서 `it`의 참고 위치와 사람이 고른 `Hallasan`의 토큰 위치 비교
- 빈칸 후보 5개 확인, 실제 사실이나 운영 정보로 해석하지 않기
- 기본값 두 입력 비교: 원문의 `highest`를 가린 입력, `mountain`을 가린 입력
- 선택 활동: **TODO 한 지점의 기존 입력 문장만 교체**, `[MASK]` 한 개 유지
- TODO를 수정하지 않아도 두 빈칸 위치의 후보 비교와 확인 질문 응답 가능

| 출력 | 읽을 내용 |
|---|---|
| 교육용 모형 | 사람이 지정한 우산 참조 비중, 학습 결과가 아님 |
| 실제 어텐션 그림 | 행=현재 위치, 열=참고 위치, 축 번호는 위의 토큰 목록과 대응 |
| `it` 상위 위치 | 특수 토큰 포함, 사람이 예상한 위치와 비교 |
| 빈칸 후보 | 작은 모델이 제안한 토큰과 어휘 분포에서의 확률 |
| 두 기본 입력 또는 수정 후 결과 | 빈칸 위치·문맥과 후보 변화의 관계, 변화가 없을 가능성도 기록 |

토큰 목록에는 `[CLS]`, `[SEP]` 같은 특수 토큰과 `##`로 시작하는 단어 조각이 나올 수 있다. 문장의 단어 하나와 토큰 하나가 반드시 일치하지 않는다는 2주차의 내용을 다시 확인한다.

### 자주 막히는 지점

| 증상 | 조치 |
|---|---|
| 설치 실패 | 셀에 출력된 오류 유형 기록, 교육용 모형으로 계속 관찰 |
| 모델 다운로드 실패 | 실제 결과 생략 사실 기록, 연결 복구 후 모델 준비 셀부터 재실행 |
| 그림 라이브러리 없음 | 출력되는 숫자 표로 가중치 관찰 |
| 빈칸 개수 오류 | 영어 문장에 `[MASK]` 정확히 하나 유지 |
| 빈칸이 길이 제한 뒤에 있음 | 문장을 짧게 바꾸고 재실행 |
| 후보가 어색함 | 오류와 구별, 작은 영어 모델의 한계로 결과 그대로 기록 |

실제 모델 사용 불가 시에도 교육용 모형의 구조를 관찰하고 답할 수 있다. 교육용 결과를 실제 모델 결과처럼 보고하거나 빈칸 후보를 만들어 쓰지 않는다.

- 평가 기준: 예상과 같은 후보가 나왔는지가 아니라 **실행 모드, 참조 위치, 해석의 한계를 정확히 기록했는지**

## 확인 질문

1. RNN이 '그것은'에서 앞의 '우산을' 정보를 사용하려면 어떤 경로가 필요한가?
2. LSTM이 정보를 유지하도록 도와도 긴 문서 이해를 보장하지 않는 이유는?
3. 어텐션의 큰 가중치를 실제 사실의 확률로 읽을 수 있는가?
4. 트랜스포머가 토큰을 함께 처리할 때 위치 정보가 필요한 이유는?
5. 여러 헤드의 기능을 '주어 담당', '대명사 담당'으로 고정해도 되는가?
6. 교육용 모형만 실행했을 때 실제 모델의 빈칸 후보를 보고할 수 있는가?

**확인 기준**

- 1: 이전 상태를 거쳐 여러 단계로 전달된 정보 사용
- 2: 정보 유지 개선과 모든 조건·관계 보존은 다른 주장, 순차 의존성과 표현 용량의 한계
- 3: 불가, 해당 행에서의 참고 비중이며 사실 검증 결과 아님
- 4: 같은 단어라도 순서에 따라 뜻이 달라지므로 위치 구별 필요
- 5: 불가, 관찰 결과와 사전에 고정된 역할 구분 필요
- 6: 불가, 교육용 모형 결과와 실제 모델 사용 실패를 구분하여 기록

## 이번 주 용어 정리

| 용어 | 뜻 |
|---|---|
| 시퀀스 | 순서가 있는 토큰 목록 |
| 상태 | 앞서 읽은 정보를 전달하는 벡터 |
| RNN | 이전 상태와 현재 입력으로 새 상태를 만드는 순환 신경망 |
| LSTM | 정보 유지·삭제를 조절하는 RNN 계열 |
| 어텐션 | 다른 위치를 참고할 비중을 계산하여 정보 결합 |
| 자기 어텐션 | 같은 입력 안의 위치끼리 참고하는 어텐션 |
| 헤드 | 별도의 참고 비중 계산 단위 |
| 위치 정보 | 토큰의 위치와 순서를 구별하는 정보 |
| 트랜스포머 | 자기 어텐션 중심의 블록을 쌓는 모델 구조 |
| 마스크 | 빈칸 토큰 또는 참고를 허용하지 않는 위치 표시, 용도 구별 필요 |
