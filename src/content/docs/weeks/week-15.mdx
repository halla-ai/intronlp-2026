## 이번 주차

학기 동안 배운 개념을 한 장의 지도와 하나의 사례 설명으로 이어 붙이는 주차. 새로운 모델을 더 실행하기보다 **무엇을 확인했고 무엇은 아직 모르는지** 드러내는 기말 프로젝트 발표와 최종 정리.

□ 이번 주에 하는 일

- **학습목표**: 말뭉치에서 통계·벡터·문맥·사전학습·LLM·사회적 함의로 이어지는 관계 설명
- **발표목표**: 팀별 사례 연구의 문제·자료·관찰·근거·한계를 구분하고 상호 질의로 점검
- **실무목표**: 도내 정주를 상정한 업무에 필요한 역량과 지금 갖춘 역량의 간격 기록
- **결과물**: 개념 지도, 기말 프로젝트 발표·결과물, 개인 진단 비교와 후속 학습 계획
- **활동 범위**: 기존 자료·기존 실행 기록의 정리. 새 모델 학습이나 새 시스템 배포 없음

원문 책은 사례의 출발점, 빈 포트폴리오와 질문 카드는 설명과 근거를 채울 자리. 학생들이 함께 살피는 장면은 실제 수업 사진이나 성과 기록이 아닌 교육용 비유. 발표는 **확인한 부분과 남은 부분을 나누어 다른 사람이 검토할 수 있게 만드는 활동**.

□ 14주차에서 이어지는 자리

- 13주차: 응용 사례에서 문제·자료·역할·판단 경계 비교
- 14주차: 편향과 가치 충돌, 근거를 확인할 수 없는 설명의 처리 논의
- 15주차: 그 판단을 학기 전체 개념과 연결해 발표하고, 질문을 받아 다음 행동 결정
- 연결 기준: 편리한 출력만 보여 주기보다 **자료의 조건·오류 가능성·사람이 확인할 자리** 함께 제시

□ 이 문서를 읽는 법

- 그림의 선택 결과는 사람이 작성한 교육용 안내. 실제 모델 출력·채용 조사·성능 측정 아님
- 사례의 공개 자료는 [제주 공개 데이터 출처](/reference/data/)에 등록된 공식 안내 발췌 재사용
- 도내 조직·담당 업무는 진로를 생각하기 위한 상정 조건. 실제 기업 데이터·구인 공고·임금 정보 없음
- 발표 예시는 기록의 작성 방법. 직접 실행하지 않은 모델 결과를 관찰 사실로 채우는 용도 아님
- 15주차에는 **별도 실습 노트북 없음**. 기존 결과와 [발표·최종 정리 양식](/worksheets/week-15/final-presentation-template.md) 사용

## 온라인 (2시수)

### 강의 1: 한 학기의 개념을 다시 연결하기

□ 새로운 방법이 나오면 이전 방법은 사라지는가

학기 앞부분은 단어의 개수와 함께 나타나는 패턴, 뒤로 갈수록 학습한 벡터와 입력 문맥을 다루는 구성. 이를 '옛날 방법은 틀리고 새 방법은 맞다'는 순위표로 읽으면 실제 업무의 선택 기준을 놓치는 문제.

단어 빈도는 무엇이 많이 언급되는지 바로 확인하는 데 쓰이고, 분류기는 정해진 범주의 구분에 쓰이는 도구. 문장 임베딩은 표현이 다른 문장을 비교하는 데 도움이 되고, 생성 모델은 주어진 입력 뒤의 텍스트를 만드는 방식. **서로 답하려는 질문이 다르므로 같은 이름의 성능으로 일렬 비교하기 어려운 관계**.

'한라산'이라는 단어가 몇 번 나오는지 알고 싶은 상황에서 긴 설명문을 생성할 필요는 없음. 비슷한 뜻의 문의를 묶고 싶은 상황에서는 단어가 같은지만 세면 놓치는 표현이 있을 수 있음. 방문자의 질문에 안내문을 읽고 답하려는 상황에서는 검색이나 생성뿐 아니라 원문 확인도 필요한 절차.

| 배우는 마디 | 중심 질문 | 제주 자료에 적용하는 예 | 남는 한계 |
|---|---|---|---|
| 언어 현상·말뭉치 | 무엇을 텍스트로 모았는가 | 공식 관광 안내를 수집한 목적 확인 | 공개 안내가 모든 이용자의 표현을 대표하지 않음 |
| 통계적 모델링 | 어떤 표현이 얼마나 자주 나타나는가 | 단어 빈도·인접 단어·분류 결과 관찰 | 빈도가 높다는 사실만으로 의미나 사실성 확정 불가 |
| 의미 표현 | 서로 다른 표현의 뜻을 어떻게 비교할까 | 단어·문장을 벡터로 바꾸어 유사도 관찰 | 가까운 벡터가 같은 사실이나 같은 입장을 보장하지 않음 |
| 신경망·트랜스포머 | 입력의 다른 부분을 어떻게 참고할까 | 어텐션 가중치의 모양 관찰 | 가중치만으로 내부 원인이나 정답 근거 확정 불가 |
| 사전학습 | 미리 배운 모델을 어떻게 활용할까 | 공개 모델을 과제에 맞게 불러와 실행 | 학습 목적·언어·입력 조건이 현재 업무와 다를 수 있음 |
| LLM 활용 | 지시·예시·자료를 어떻게 제공할까 | 같은 질문에서 입력 문맥을 바꾸어 출력 비교 | 지시 준수와 사실성이 항상 함께 개선되는 것은 아님 |
| 사회적 함의 | 누구의 불이익과 판단 책임을 볼까 | 방언 표현의 누락·근거 없는 답의 위험 검토 | 기술 관찰만으로 가치 판단과 책임 결정 완료 불가 |

□ '말뭉치'에서 시작해야 하는 이유

**말뭉치**는 분석이나 학습을 위해 모은 텍스트의 묶음. 어떤 글을 골랐는지에 따라 단어 빈도도, 드러나는 주제도 달라지는 출발점. 안내문만 모았다면 서비스 문의·불만·방언 대화에서 나타나는 표현은 적거나 없을 수 있는 조건.

텍스트를 작은 단위로 나누는 **토큰화**도 결과를 바꾸는 선택. 조사와 띄어쓰기 때문에 같은 뜻의 한국어 표현이 다른 조각으로 나뉠 수 있다는 2주차의 관찰을 여기서 다시 사용. 모델이 크다는 이유로 입력 자료의 누락이 자동으로 사라지는 것은 아님.

발표에서는 '공개 자료 사용'만 말하지 않고 **자료의 종류·대상·빠진 표현**을 함께 기록. 관광 소개문으로 이용자의 불만을 알아낼 수 있다고 주장한다면, 자료의 목적과 과제의 목적 사이에 간격이 있다는 점부터 검토할 필요.

□ 통계적 모델에서 의미 표현으로

**N-그램**은 연속한 N개의 토큰을 묶어 주변 패턴을 세는 방법. **조건부 확률**은 앞의 조건을 알고 있을 때 뒤의 사건이 얼마나 자주 나타나는지 나타내는 값. '이 앞말 뒤에서 어떤 표현이 자주 나왔는가'라는 질문을 관찰 기록으로 바꾸는 방식.

4주차의 **HMM(숨겨진 마르코프 모델)**도 통계적 모델링에 포함. 눈에 보이는 단어 열에서 직접 보이지 않는 품사 열을 추정하는 과제. N-그램이 다음 토큰의 가능성을 묻는 자리라면 HMM 태깅은 각 위치에 어떤 품사가 놓일지를 묻는 자리. **단어의 순서와 이웃 조건을 이용한다는 연결**, 예측 대상은 다르다는 차이를 함께 정리. 제공 형태소 분석기의 실행과 HMM 자체를 새로 구현한 경험도 구분.

**분류**는 텍스트를 미리 정한 범주 중 하나로 나누는 과제. 긍정·부정 결과가 나와도 입력이 사실인지, 방문자가 이용해도 안전한지는 다른 질문. 5주차에 배운 정확도의 한계를 떠올리면, 한 번 잘 맞은 결과를 전체 업무의 안전성으로 바꾸지 않을 이유를 설명할 수 있는 구조.

**임베딩**은 단어나 문장을 숫자 벡터로 나타내는 방식. 숫자 벡터는 여러 칸에 값을 담은 표현이며, 칸의 수가 늘었다고 뜻이 자동으로 정확해지는 것은 아님. 표현 사이의 거리를 비교할 수 있다는 장점과, 반대 뜻이 비슷하게 나타날 수 있다는 한계를 함께 설명할 필요.

| 이어지는 관계 | 앞에서 배운 것 | 뒤에서 달라진 것 | 그대로 남는 확인 |
|---|---|---|---|
| 토큰화 → 빈도 | 텍스트를 나누는 기준 | 각 조각의 출현 횟수 계산 | 조사·띄어쓰기·누락 처리 |
| 빈도 → N-그램 | 관찰한 출현 횟수 | 앞뒤 조건을 함께 계산 | 보지 못한 표현의 처리 |
| 동시발생 → 임베딩 | 비슷한 주변 표현의 단서 | 학습한 숫자 표현으로 비교 | 말뭉치의 대표성과 유사도의 뜻 |
| 단어 벡터 → 문장 벡터 | 단어의 의미 비교 | 문장 단위 비교와 검색 | 부정·수치·조건 차이 |
| 문장 비교 → 문맥 처리 | 입력 표현 사이의 관계 | 현재 문장 안의 다른 부분 참고 | 모델 과제와 실제 용도의 적합성 |

□ 트랜스포머에서 사전학습·LLM으로

**어텐션**은 입력의 다른 위치를 참고하는 가중치를 계산하는 장치. 가중치는 관찰할 수 있는 숫자지만 사람이 이해하는 의도·사실 근거와 같은 것은 아님. 9주차에서 본 그림을 '어느 토큰을 많이 참고했는가'의 기록으로 설명하는 것이 범위에 맞는 해석.

**사전학습**은 현재 과제 이전에 큰 텍스트 자료 등으로 모델을 미리 학습하는 과정. **추론**은 이미 정해진 모델을 입력에 적용해 결과를 얻는 실행. 공개 모델을 불러와 실행한 활동은 후자의 경험이며, 우리가 모델을 처음부터 학습했다는 근거가 되지 않는 구분.

**문맥학습**은 현재 입력에 들어 있는 지시·예시를 활용하는 현상. 이번 학기 실행에서는 모델의 가중치를 유지한 채 예시를 바꾸었으므로 **미세조정**, 즉 추가 학습으로 가중치를 바꾸는 과정과 구분. 예시를 넣었다는 겉모양만 보고 같은 학습으로 묶지 않는 기준.

LLM은 큰 규모의 언어모델을 부르는 이름. 입력에 따라 긴 설명을 만들어도 원문에 없는 시간·요금을 덧붙일 수 있는 문제. **길게 설명할 수 있다는 능력과 중요한 주장을 확인했다는 사실은 별도 항목**. 그래서 11·12주차는 입력 설계와 근거 대조를 함께 수행한 구성.

돌 개수 기록은 통계적 관찰, 벡터 화살표는 숫자 표현, 원문 책과 답 카드는 문맥 활용과 근거 대조의 비유. 흰 화살표는 다음 개념으로의 연결, 되돌아오는 경로는 앞의 자료와 개념을 다시 점검하는 관계. 실제 모델 구조나 성능 흐름의 증거는 아님. '무엇이 이어지고 무엇을 다시 확인하는가'를 한 문장씩 말하는 연습.

□ 그림을 읽고 개념 연결하기

1. '통계적 모델링' 선택 후 단어 빈도와 N-그램의 질문 차이 확인.
2. '의미 표현' 선택 후 유사도와 사실 확인의 차이 기록.
3. 'LLM 활용' 선택 후 문맥학습과 추가 학습의 차이 기록.
4. '사회적 함의' 선택 후 기술 관찰에서 사람의 판단으로 넘어가는 자리 표시.

그림은 관계를 골라 읽는 안내이며 모델 실행은 없음. 화면의 예시는 관찰된 정확도나 우열이 아니라 **개념을 설명할 수 있는 질문**. 자신의 프로젝트에서 선택한 방법의 장점 한 가지와 남는 한계 한 가지를 추가하면 완성되는 지도.

### 강의 2: 근거 있는 사례 설명과 다음 학습 계획

□ 다섯 질문을 순서대로 연결하기

학기 동안 대면 활동에서 사용한 질문을 한 번에 묶는 단계. Q1은 문제 정의, Q2는 이해관계자, Q3는 가치 충돌, Q4는 근거 기준, Q5는 판단 보류. 번호를 외우는 것보다 **문제의 범위에서 판단의 경계까지 연결하는 기능** 이해.

| 질문 | 쉬운 풀이 | 사례 발표에서 적을 내용 |
|---|---|---|
| Q1 문제 정의 | 무엇이 불편하고 어떤 답이 필요한가 | 공개 안내를 읽는 방문자의 질문 범위 |
| Q2 이해관계자 | 결과를 받거나 영향을 받는 사람이 누구인가 | 방문자·안내 담당자·자료 제공자의 다른 필요 |
| Q3 가치 충돌 | 좋은 목표끼리 동시에 만족하기 어려운 곳은 어디인가 | 빠른 답변과 확인된 안내 사이의 절충 |
| Q4 근거 기준 | 무엇을 보면 이 주장을 받아들일 수 있는가 | 원문 표현·수치·단위·열람일과 주장 대조 |
| Q5 판단 보류 | 어떤 결정은 아직 맡기거나 확정하면 안 되는가 | 근거가 없거나 자료가 충돌하는 이용 조건 |

**이해관계자**는 결과의 이익이나 불이익에 영향을 받는 사람·집단. Q2는 데이터 이름을 묻는 질문이 아님. 자료를 읽는 일은 Q4의 근거 확인에서도 수행하지만, 누구의 입장을 고려할지는 따로 결정해야 하는 관계.

**가치 충돌**은 두 목표를 모두 최대한 만족시키기 어려운 상황. 방문자는 짧은 답을 원하고 담당자는 빠른 처리를 원할 수 있지만, 근거 없는 정보가 포함되면 오안내를 받는 사람이 생길 수 있는 조건. 짧음·빠름을 버리라는 뜻보다 **생략해도 되는 정보와 확인해야 하는 정보의 경계** 설정.

□ 어떤 주장을 근거로 확인한 것인가

'H 발췌에는 한라산 높이가 1,950m로 적혀 있다'는 원문 내용에 대한 주장. '오늘 한라산의 모든 탐방로를 이용할 수 있다'는 최신 이용 조건에 대한 주장. 앞의 문장을 확인했다고 뒤의 문장도 확인한 것은 아님.

'O 발췌에 11km라고 적혀 있다'는 선택한 문장과 맞는 설명이지만, 페이지 다른 곳의 표기와 다르다는 정보까지 함께 알고 있는 상황. 발표에서 그 불일치를 숨기면 **발췌 일치가 최신 현장 사실의 확인처럼 보일 위험**. '발췌 기준 답은 확인, 실제 최신 길이는 보류'로 구분할 필요.

'걷는 시간이 몇 시간인가'는 현재 두 발췌에 답이 없는 질문. 거리가 제시되었다고 속도·휴식·우회 조건이 정해진 것은 아니므로 시간을 계산하려면 추가 가정 필요. 그 계산을 하더라도 원문 사실이 아니라 가정에 따른 예시 계산으로 표시할 조건.

□ 그림에서 확인할 것

- '높이 발췌' 선택: 원문 표현과 발표 주장의 관계 확인
- '최신 코스 길이' 선택: 한 발췌가 맞더라도 자료 충돌 때문에 보류할 이유 확인
- '걷는 시간' 선택: 답이 없는 질문을 빈칸으로 남기는 처리 확인
- '실행 기록' 선택: 자료의 내용과 팀이 실제로 얻은 출력을 구분하는 기준 확인

선택을 바꾸어도 실제 모델 호출은 없음. 그림의 목적은 숫자를 맞히는 게임보다 **주장이 달라지면 필요한 근거도 달라진다**는 관계 확인. 발표의 각 결론 옆에 이 구조의 확인 상태를 붙이는 연습.

□ 다음 학습을 '도구 목록' 대신 역량 간격으로 쓰기

**역량 간격**은 하려는 업무에 필요한 능력과 현재 근거를 가지고 보여 줄 수 있는 능력 사이의 차이. '언어모델을 배웠다'는 수강 사실만 적기보다, '공개 자료의 주장과 근거를 대조할 수 있다'처럼 행동으로 표현하는 방식.

도내 정주는 제주에서 생활하며 업무를 이어 가는 경로를 생각하는 맥락. 다음 표는 실제 채용시장 조사나 취업 약속이 아니라 **업무를 상정해 개인 학습 방향을 정하는 연습**. 채용 여부·임금·기관 실적을 이 수업 결과로 추정하지 않는 범위.

| 상정 업무 | 필요한 행동 | 지금 보여 줄 수 있는 근거 | 더 배울 부분 |
|---|---|---|---|
| 공개 안내 자료 정리 | 출처·열람일·문서 버전 정리 | 사례의 원문·가공 기록 | 자료 변경 확인과 관리 절차 |

| 도구 결과 설명 | 출력·실행 조건·한계 전달 | 기존 노트북과 보고서 | 오류 유형 분석과 협업 문서 작성 |
| 지역 표현 검토 | 다른 표현의 누락·불이익 확인 | 방언 사례의 조건 기록 | 대표성 있는 자료와 평가 절차 |

□ 후속 과목으로 넘어가는 내용

후속 **딥러닝자연어처리**는 모델을 어떻게 구현·학습·조정하고 실제 시스템으로 연결할지 더 깊이 다루는 경로. 이번 과목에서 개념을 알아본 경험이 그 학습의 출발점이며, 이름을 들었다는 이유로 이미 구현할 수 있다고 간주하지 않는 구분.

'설명할 수 있다'는 표시는 짧은 설명과 예시로 확인. 예를 들어 임베딩을 설명할 수 있다고 표시했다면, 비슷한 벡터가 같은 사실을 보장하지 않는 이유까지 자기 말로 덧붙이는 방식. 기억하는 용어 수보다 관계를 설명하는 근거에 초점.

### 기말 프로젝트 팀별 발표와 상호 질의

□ 발표 전에 정리할 자료

기말 프로젝트는 13주차의 사례 조사와 14주차의 책임 있는 판단을 이어받는 활동. 팀이 선택한 주제의 문제·공개 자료·기술의 역할·사회적 조건을 한 흐름으로 설명하고, 질문을 통해 범위와 근거를 다시 확인하는 단계.

보고서·발표 자료의 새 디자인이나 새 모델 실행보다 **검토할 수 있는 기록의 연결**부터 점검. 자료를 읽은 날짜, 인용할 원문, 작성한 가정, 실행 결과의 조건, 미확인 상태를 구분해 놓으면 같은 자료를 보면서 질문에 답할 수 있는 준비.

| 발표의 부분 | 들어갈 내용 | 준비 확인 |
|---|---|---|
| 문제와 대상 | 누구의 어떤 불편을 다루는가 | Q1과 Q2가 구분되어 있는가 |
| 공개 자료 | 출처·열람일·발췌·가공·이용 조건 | 원문과 작성한 예시를 나누었는가 |
| 기술과 역할 | 어떤 과제에 어떤 방법을 쓰는가 | 분류·검색·생성을 섞어 말하지 않았는가 |
| 결과와 근거 | 실제 관찰과 그 판단 기준 | 출력이 있으면 실행 조건과 전문이 있는가 |
| 충돌과 경계 | 누가 불이익을 받을 수 있는가 | Q3와 Q5의 이유가 자료 조건과 연결되는가 |
| 다음 선택 | 확인·수정·보류 중 다음 행동 | 담당 확인 항목이나 필요한 자료가 구체적인가 |

**근거 사슬**은 주장부터 원문·실행 기록·판단까지 이어지는 연결. 발표의 흐름을 점검하기 위한 말이며 새 채점 항목의 이름 아님. 기말 프로젝트 비중은 수업계획서의 **20%**, 기말고사는 **10%**. 세부 일정·발표 시간·팀 구성·채점 기준은 교수 안내 확인.

### 발췌와 주장을 연결하는 발표 연습

□ 교육용 발표 문장과 수정

다음 문장은 기록을 고치는 연습 예시. 실제 팀 발표나 실제 모델 출력의 인용 아님. 유창함을 높이는 교정이 아니라 어떤 결론까지 말할 근거가 있는지 줄이는 교정.

| 초안 문장 | 문제 | 범위를 드러낸 수정 예시 |
|---|---|---|
| '이 방법이면 관광 안내를 정확히 할 수 있음' | 전체 업무의 정확성을 확인한 기록 없음 | '제공 발췌와 대조한 범위, 미확인 이용 조건을 구분해 안내할 필요' |
| '올레 6코스 길이는 11km로 확정' | 같은 페이지의 다른 표기 누락 | '제공 발췌에는 11km, 상단에는 다른 표기. 최신 길이 확인은 보류' |
| '모델이 이유를 설명했으니 맞는 답' | 설명과 원문 근거 혼동 | '설명은 생성 결과로 보고, 원문 표현과 주장을 별도로 대조' |
| '우리 팀이 모델을 학습함' | 기존 모델 실행과 학습 혼동 가능 | '제공된 모델을 불러와 입력에 적용. 추가 학습 수행 여부는 따로 표시' |

발표자가 '아직 확인하지 못했다'고 말할 때는 무엇이 비어 있는지까지 설명할 필요. '모두 불확실함'으로 끝내면 이미 확인한 내용도 사라지고, '작은 표본이지만 전체에 효과 있음'으로 끝내면 범위가 커지는 문제. **확인한 범위와 확인하지 못한 범위를 함께 좁히는 표현** 사용.

답 카드 옆에 인용 표시가 있는 원문을 두고, 미확인 메모와 질문표 카드를 함께 배치한 교육용 비유. 생각 버블은 실제 모델 내부의 생각이나 판단 증거가 아님. 발표의 결론이 바뀌면 연결된 원문과 확인 상태도 함께 바뀌어야 하는 관계. 출처 목록이 길어도 주장과 연결되지 않으면 그 결론을 확인한 것은 아님.

### 상호 질의에서 다음 행동으로

□ 질문하는 사람의 역할

상대가 모르는 것을 찾아내는 활동보다 **어느 연결이 아직 부족한지 함께 확인하는 활동**. '왜 큰 모델을 안 썼는가'처럼 모델 크기만 묻기보다, 현재 과제에서 어떤 조건과 결과로 선택했는지 질문하는 방식.

| 확인할 자리 | 질문 예시 | 답변에 필요한 기록 |
|---|---|---|
| 문제 범위 | '이 결과는 어떤 질문까지 답할 수 있는가?' | 포함·제외 질문 |
| 자료의 대표성 | '이 안내문에 없는 이용자 표현은 무엇인가?' | 자료 종류와 빠진 집단 |
| 실행 상태 | '이 문장은 실제 출력인가, 교육용 예시인가?' | 실행 로그 또는 작성 예시 표시 |
| 근거 | '이 숫자를 뒷받침하는 원문 위치는 어디인가?' | 발췌·URL·열람일 |
| 오류와 영향 | '틀리면 누가 어떤 불이익을 받을 수 있는가?' | 이해관계자와 검토 절차 |
| 다음 행동 | '확인하려면 무엇을 더 보아야 하는가?' | 필요한 자료·확인 경로 |

□ 피드백을 받는 사람의 역할

1. 질문이 자료·결과·판단 중 어느 부분인지 먼저 확인.
2. 현재 기록으로 답할 수 있으면 해당 원문·조건 제시.
3. 답할 수 없으면 부족한 근거와 보류할 결론 표시.
4. 피드백을 반영해 주장 범위·가공 표시·다음 행동 중 필요한 항목 수정.

'시간이 부족해서 답하지 못함'과 '근거가 없어 답할 수 없음'은 다른 상태. 전자는 준비한 자료를 다시 찾아 전달할 수 있고, 후자는 추가 확인 전 결론 보류가 필요. 질문을 받았다는 사실만 기록하지 않고 처리 상태까지 남기는 순서.

| 받은 피드백 | 확인한 상태 | 다음 행동의 기입 예시 |
|---|---|---|
| '코스 거리 표기가 다름' | 발췌와 상단의 불일치 확인 | 최신 길이 주장 보류, 공식 안내 추가 확인 항목 작성 |
| '출력이 실제 실행인지 불명확' | 해당 실행 기록이 있는지 확인 | 있으면 연결, 없으면 예시 또는 미실행으로 수정 |
| '방언 이용자의 입장이 빠짐' | 자료에 해당 표현이 없는 조건 | 누락 가능성 설명, 적용 범위에서 제외한 이유 기록 |
| '생성 답이 과제를 해결했다는 근거 부족' | 형식 준수만 확인했을 가능성 | 내용 일치·누락·근거 없는 추가를 구분해 재대조 |

□ 최종 정리에서 남길 것

- 팀 기록: 실제로 사용한 자료·방법·관찰·판단 경계·질의응답 반영 사항
- 개인 기록: 1주차 진단과 현재 설명의 차이, 아직 설명하기 어려운 마디
- 학습 계획: 상정 업무와 연결한 구체적 다음 행동, 확인할 결과물
- 제출 경로: `assignments/week-15/<학번>/`. 이름·연락처나 다른 학생의 정보 미포함
- 팀 기여도 분쟁·평가 예외·최종 성적은 교수에게 확인. 이 자료에서 새 규칙 확정 없음

## 학습활동

### [이론] 개념 지도와 처음의 진단 대조

□ 기본 단계

일곱 마디를 적고 '이전 마디를 이용해 다음 마디에서 무엇을 설명하는가'를 화살표 옆에 작성. 수식·구현 세부가 없어도 개념의 관계가 맞으면 되는 활동. 용어만 나열한 지도와 관계를 설명한 지도는 다르게 읽히는 결과.

| 지도에 적을 연결 | 작성할 문장의 골격 | 자기 확인 |
|---|---|---|
| 말뭉치 → 통계 | '무엇을 모았는지에 따라 ...가 달라짐' | 자료 목적과 단어 분포 연결 |
| 통계 → 벡터 | '주변에 함께 나타난다는 단서를 ...에 사용' | 빈도와 의미 표현 구분 |
| 벡터 → 문맥 | '같은 단어도 현재 문장에 따라 ...' | 고정 표현과 입력 문맥 구분 |
| 문맥 → LLM 활용 | '지시·예시를 입력에 넣으면 ...' | 현재 입력과 추가 학습 구분 |
| 출력 → 사회적 판단 | '그럴듯한 답이어도 ... 확인 필요' | 사실성·피해·책임 구분 |

□ 더 확인할 단계

1주차의 활동 B와 같은 상태 표현을 사용하고 현재 설명의 근거 한 문장 추가. 기록이 달라진 이유를 '공부를 많이 해서'로 끝내기보다, 어느 실습의 어떤 결과로 이해가 바뀌었는지 연결. 옛 기록이 없으면 없음으로 남기는 방식.

### [구현] 기존 사례의 발표와 상호 질의

□ 기본 단계

[발표·최종 정리 양식](/worksheets/week-15/final-presentation-template.md)을 복사하고 자신의 기존 결과물과 연결. 코드 작성·새 TODO·새 노트북 생성은 없음. 실행한 경우 실제 결과, 실행하지 않은 경우 자료 분석과 미실행 상태를 기록하는 활동.

- 문제·이해관계자·가치 충돌·근거·판단 보류를 Q1~Q5 칸에 작성
- 자료마다 출처·열람일·발췌·가공 여부 작성
- 기존 출력이 있으면 실행 조건과 전문을 연결하고 주장별로 대조
- 실제 출력이 없으면 그 칸에 미실행 표시. 원문 분석을 모델 평가로 바꾸지 않는 기준
- 발표 후 질문 하나와 그 질문에 따라 수정한 부분 기록

□ 더 확인할 단계

동료의 발표를 들으며 자료와 주장을 연결할 수 있는지 확인. 같은 방법을 선택했더라도 자료·문제·이해관계자가 다르면 결론이 달라질 수 있는 이유 정리. 다른 팀의 성적이나 개인정보를 기록하는 활동 아님.

### [실무] 도내 정주 경로와 후속 학습 계획

□ 기본 단계

상정 업무 하나를 고르고 현재 보여 줄 수 있는 결과물을 연결. 처음부터 'AI 개발자'라는 직업명 전체를 목표로 잡기보다 공개 자료 정리·문의 검토·결과 설명처럼 관찰 가능한 행동으로 좁히는 방식.

| 계획 항목 | 기입 예시 | 확인할 결과 |
|---|---|---|
| 상정 업무 | 공개 안내 자료와 질문을 정리하는 업무 | 실제 채용 사실이 아니라는 표시 |
| 현재 근거 | 발췌·가공·열람일을 구분한 사례 기록 | 원문과 연결된 문서 |
| 남은 간격 | 자료 변경과 불일치 처리 경험 부족 | 보류 이유를 구체적으로 설명 |
| 다음 행동 | 기존 자료의 표기 차이를 다시 점검하고 변경 기록 작성 | 수정 전후와 판단 상태 |
| 후속 학습 | 검색·생성 결합의 평가 방법 더 학습 | 검색 결과와 답 근거를 나눈 연습 |

□ 더 확인할 단계

교수와 상담할 때는 '다음에 무엇을 하면 되는가'만 묻지 않고 현재 기록과 막힌 지점을 함께 제시. Python 기초가 막힌 경우와 모델 결과 해석이 막힌 경우는 학습 행동이 다른 조건. 상담에서 새로운 정책이나 취업 결과를 약속받았다고 기록하지 않는 범위.

□ 제출 전 확인

- 개념 지도의 각 연결에 자기 설명 존재
- 사전 진단 원본의 유무와 현재 상태를 구분해 기록
- 기말 프로젝트 발표·결과물의 출처와 실제 관찰 상태 표시
- Q1~Q5의 역할을 바꾸지 않고, 팀 사례에서 각 질문에 답변
- 근거 없는 주장·원문 불일치·미실행 항목은 미확인 상태 유지
- 상호 질의와 수정 또는 보류 이유 기록
- 개인 학습 계획에 다음 행동과 확인할 결과물 연결
- 교수의 제출 안내 확인. 이 문서에서 새로운 일정·시간·배점 세부 확정 없음

## 자주 하는 오해 Q&A

<details>
<summary>Q1. 큰 언어모델을 배우면 빈도·N-그램·분류기는 더 쓸 필요가 없는가?</summary>

아님. 단어 수를 확인하는 과제, 정해진 범주를 나누는 과제, 긴 텍스트를 생성하는 과제는 목적이 다름. 비용·설명 가능성·자료 조건·검토 부담을 포함해 선택할 필요. 새로운 방법이 더 많은 일을 할 수 있어도 현재 문제를 더 적절하게 해결한다는 결론은 실제 조건과 결과로 확인.

</details>

<details>
<summary>Q2. 개념 지도를 외우면 학기 내용을 설명할 수 있다고 표시해도 되는가?</summary>

이름을 말하는 것과 관계를 설명하는 것은 다른 상태. '벡터가 가까워도 같은 사실은 아닐 수 있음'처럼 한계와 사례를 연결해 자기 말로 설명하는 근거 필요. 지도는 설명을 돕는 도구이며 암기한 순서를 말하는 것이 유일한 목표 아님.

</details>

<details>
<summary>Q3. 처음의 사전 진단이 없으면 지금 기억으로 이전 상태를 채우는가?</summary>

이전 기록은 없다고 표시하고 현재 상태만 작성. 기억을 바탕으로 한 회고는 회고로 적을 수 있지만 당시 작성한 진단 기록처럼 제시하지 않는 구분. 확인되지 않은 학기 초 상태로 변화량이나 성적을 주장하지 않는 기준.

</details>

<details>
<summary>Q4. 발표에 출처 목록이 있으면 모든 결론의 근거가 있는 것인가?</summary>

아님. 해당 결론을 뒷받침하는 원문 위치와 표현을 연결해야 검토 가능. 높이 발췌가 있다고 탐방 가능 여부까지 확인된 것은 아님. 출처·주장·확인 상태를 연결하고 자료에 없거나 충돌하는 항목은 보류할 필요.

</details>

<details>
<summary>Q5. 최신 코스 길이를 확정하지 못하면 발표가 실패한 것인가?</summary>

현재 자료로 무엇이 확인되고 무엇이 보류되는지 설명하는 것도 결과. 제공 발췌의 내용과 실제 최신 길이는 서로 다른 주장. 표기 불일치를 발견했다면 보류 이유와 추가 확인 경로를 남기는 것이 근거 없는 확정보다 적절한 처리.

</details>

<details>
<summary>Q6. 실제 모델 실행이 없는 사례 분석에도 가상의 출력을 넣어 비교하는가?</summary>

넣지 않는 원칙. 원문 분석과 개념 적용은 그 자체의 활동으로 기록하고 실행 결과는 미실행 표시. 사람이 만든 설명 예시를 사용할 때는 교육용 예시라고 명시. 실행하지 않은 결과를 모델 성능이나 실제 성공 사례로 제시하지 않는 기준.

</details>

<details>
<summary>Q7. 도내 정주 업무 지도를 따르면 제주에서 해당 직무에 취업할 수 있는가?</summary>

이 지도는 업무와 학습 행동을 연결하기 위한 상정 연습. 실제 채용 공고·임금·기관 실적을 조사한 자료가 아니므로 취업 가능성을 확정할 수 없음. 필요한 역량과 현재 근거의 간격을 정리해 향후 상담과 학습 계획에 활용.

</details>

<details>
<summary>Q8. 기말 발표에서 미세조정·RAG·에이전트·배포를 새로 구현해야 하는가?</summary>

아님. 이번 주는 사례 발표와 최종 정리. 해당 주제는 이름과 목적을 이해하고 후속 딥러닝자연어처리에서 심화할 로드맵으로 안내. 새 구현을 덧붙여 범위를 넓히기보다 현재 자료·관찰·한계를 정확히 설명하는 활동.

</details>

## 스스로 점검

1. 통계적 모델링에서 벡터 표현으로 넘어갈 때 이어지는 단서와 새로 달라진 표현을 설명.
2. 어텐션 가중치를 본 것과 답의 사실 근거를 확인한 것의 차이를 설명.
3. 공개 모델을 불러와 실행한 활동과 미세조정의 차이를 바꾸는 대상으로 설명.
4. Q1~Q5의 이름을 적고 자신의 사례에서 각 질문에 한 문장씩 답변.
5. H 발췌로 확인할 수 있는 주장과 확인할 수 없는 주장 하나씩 기록.
6. 올레 거리 표기가 다를 때 제공 발췌의 답과 실제 최신 거리의 판단을 구분.
7. 1주차 사전 진단 원본이 없을 때 현재 비교 기록을 어떻게 작성할지 설명.
8. 상정 업무 하나에 현재 근거·남은 간격·다음 행동·확인할 결과를 연결.

1. 주변에 함께 나타나는 표현이 의미의 단서가 된다는 연결. 빈도·동시발생 관찰에서 학습한 숫자 벡터의 비교로 표현 방식이 달라짐. 벡터가 비슷해도 같은 사실이라는 보장은 없다는 한계까지 포함.
2. 가중치는 입력 위치를 참고하는 계산에서 나온 관찰값. 사실 근거 확인은 주장과 원문의 표현·숫자·단위·조건을 대조하는 절차. 참고 정도를 보았다고 내부 원인이나 외부 사실을 증명한 것은 아님.
3. 실행은 이미 정해진 가중치를 입력에 적용. 미세조정은 추가 자료로 가중치를 변경. 입력에 예시를 넣는 문맥학습도 이번 실행에서는 가중치 변경과 구분.
4. Q1 문제 정의, Q2 이해관계자, Q3 가치 충돌, Q4 근거 기준, Q5 판단 보류. 각 답이 사례의 범위·영향받는 사람·절충·원문 대조·미확인 조건과 연결되면 적절한 설명.
5. H에 높이가 1,950m로 적혀 있다는 주장은 발췌 대조 가능. 오늘의 탐방 가능 여부·운영시간·요금은 이 발췌로 확인 불가. 원문 내용에 대한 확인과 현재 현장 조건에 대한 확인 구분.
6. 제공 O 발췌의 거리 표현은 11km로 확인. 같은 페이지에 다른 표기가 있으므로 실제 최신 길이를 하나로 확정하는 판단은 보류. 추가 공식 확인이 필요하다는 상태 기록.
7. 원본 없음으로 표시하고 같은 일곱 마디에 현재 상태와 설명 근거 작성. 과거 기록을 복원한 것처럼 채우거나 확인되지 않은 변화량을 만들지 않는 원칙.
8. 예: 공개 안내 정리 업무, 출처·열람일 기록이라는 현재 근거, 변경 관리 경험이라는 간격, 표기 불일치 재점검이라는 행동, 수정 전후와 보류 상태를 연결한 문서라는 확인 결과. 실제 채용 사실로 표현하지 않는 조건 포함.
