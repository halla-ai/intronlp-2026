## 이번 주차

- **LLM**: 많은 글에서 언어 패턴을 익혀 다양한 지시에 응답하는 대규모 언어모델
- **문맥학습**: 입력에 넣은 설명과 예시를 참고해 이번 답의 방식 조정

| 비교 | 10주차 | 11주차 |

## 온라인 (2시수)

### 강의 1: LLM과 문맥학습

#### LLM은 무엇인가

앞서 배운 언어모델의 핵심은 문맥에서 다음 토큰을 예측하는 방식. 대규모 언어모델은 많은 데이터와 큰 모델을 이용해 다양한 언어 패턴을 익히고, 지시를 따라 응답하도록 추가 준비한 모델도 포함하는 범주.

**규모가 크다는 말은 정답 자료집이라는 뜻이 아님.** 모델 내부에는 학습 과정에서 조정한 숫자가 있으며, 질문마다 공식 원문을 자동 조회하는 보장은 없음.

- 문장 생성: 주어진 문맥에 이어질 토큰의 반복 선택
- 지시 응답: 요약, 분류, 질문 답변 등의 지시를 입력으로 받는 활용
- 지식의 한계: 학습 자료의 오류·빈틈·오래된 내용 반영 가능
- 출력의 한계: 자연스럽지만 근거 없는 내용 생성 가능
- 이번 실습: 이미 완성된 작은 공개 모델로 현상 확인. 대형 모델 학습 제외

#### 모델이 커지면 무엇이 달라지는가

모델·데이터·학습 자원을 늘리면 여러 과제에서 더 복잡한 패턴을 다룰 여지가 생기는 경향. 하지만 **어떤 질문에서 얼마나 좋아지는지는 평가 자료로 확인할 문제**.

| 기대할 수 있는 변화 | 함께 확인할 한계 |
|---|---|
| 다양한 표현과 긴 지시 처리 | 입력 언어와 과제별 편차 |
| 여러 예시의 형식 참고 | 잘못된 예시를 따를 가능성 |
| 복잡한 질문에 대한 응답 | 사실과 다른 응답 가능성 |
| 더 풍부한 글 생성 | 메모리·시간·검토 비용 증가 |

이번 노트북의 작은 두 모델로 규모 확대 효과를 측정하지 않는 범위. 모델 크기만 보고 제주 관광 업무 적합성이나 사실성 단정 불가.

#### 입력에 예시를 넣는 이유

관광 안내 답변의 형식을 처음 설명하는 상황의 가정. "짧게 답해 주세요"라는 말에 더해, 원하는 답 한두 개를 먼저 보여 주면 출력 형식을 구체적으로 전달 가능.

- zero-shot: 원하는 과제와 규칙만 제시, 답변 예시 없음
- few-shot: 과제와 규칙에 더해 소수의 입력·답변 예시 제시
- 문맥학습: 현재 입력 안의 예시를 참고하는 과정
- 미세조정과의 차이: 모델 내부의 숫자를 새로 학습해 바꾸는 과정 아님

<FigureFrame src="/interactive/week-11/few-shot.html" title="예시 유무에 따른 입력 구성 비교" height="390px" />

그림에서 바뀌는 것은 **모델에 전달할 입력**. 사람이 정해 둔 예시 답을 넣는 시연이며 모델이 더 좋은 답을 했다는 성능 증거가 아님.

#### 이번 실습의 질문과 예시

공개 발췌에는 `Route 6`, `11-kilometer`, `coastal and urban trail`이 기재된 상태. 발췌에는 요금과 운영시간 정보 없음.

| 입력 요소 | 사용 내용 |
|---|---|
| 공개 원문 | 올레 6코스의 길이와 성격을 설명한 짧은 절 |
| 동일 질문 | 6코스의 길이와 입장 요금 질문 |
| 공통 규칙 | 원문만 사용, 없으면 UNKNOWN, 짧은 근거 인용 |
| few-shot 예시 1 | 코스 번호 6, 운영시간 UNKNOWN |
| few-shot 예시 2 | 해안 여부 답변과 `coastal and urban trail` 근거 |
| 확인 기준 | KM=11, FEE=UNKNOWN |

`UNKNOWN`은 이 발췌에서 확인하지 못했다는 뜻. 실제 요금이 없거나 무료라는 뜻이 아님. 별도의 공식 요금 자료를 확인하기 전에는 답의 범위를 넓히지 않는 기준.

#### 예시가 항상 도움을 주는가

few-shot은 답의 형식이나 기준을 전달하는 수단. 정확성 향상의 보장은 아님.

- 좋은 예시: 원문의 정보를 사용하고 없는 값은 미확인 처리
- 나쁜 예시: 없는 사실을 지어내거나 잘못된 형식을 반복
- 소수 예시의 한계: 다른 질문이나 긴 문서에서도 유지되는지 별도 확인 필요
- 실제 결과의 기록: 변화 없음, 형식만 개선, 더 나쁜 답도 그대로 기록

#### 강의 1에서 꼭 가져갈 것

1. LLM의 언어 생성 능력과 공식 사실 확인 능력의 구분
2. zero-shot과 few-shot의 차이는 현재 입력의 예시 유무
3. 문맥학습과 모델 내부 숫자를 바꾸는 학습의 구분
4. 규모 확대와 few-shot 모두 과제별 검증 필요

### 강의 2: 추론형 모델과 근거 확인

#### 왜 답 전에 풀이를 생성하는가

여러 조건을 함께 확인해야 하는 질문에서, 답을 바로 내놓기보다 조건을 나누고 중간 결과를 정리하는 방식의 활용. 추론형 모델은 이런 풀이를 생성한 뒤 답을 내놓는 동작을 관찰할 수 있는 모델.

- 바로 답하는 출력: 질문에 대한 답을 먼저 제시하는 형태
- 풀이를 포함한 출력: 조건 확인·계산·검토와 같은 텍스트 뒤에 답 제시
- 잠재적 이점: 복잡한 문제에서 중간 단계를 활용할 여지
- 비용: 생성 토큰과 대기 시간 증가 가능
- 한계: 긴 풀이에서도 오해·계산 오류·근거 없는 주장 발생 가능

<FigureFrame src="/interactive/week-11/answer-process.html" title="짧은 답과 풀이 뒤 답의 구분 및 길이 제한" height="370px" />

**보이는 풀이도 모델이 생성한 텍스트.** 모델의 실제 내부 상태를 충실하게 설명한다는 증거와 구분. 읽기 쉬운 풀이, 긴 풀이, 정답은 서로 다른 평가 항목.

#### 일반 모델과 추론형 모델 비교의 범위

이번 실습에서는 서로 다른 작은 공개 모델에 **같은 공개 원문과 질문** 입력.

| 구분 | 일반 모델 | 추론형 모델 |
|---|---|---|
| 식별자 | Qwen2.5-0.5B-Instruct | Qwen3-0.6B |
| 사용 방식 | 지시 응답 | thinking 모드 |
| 새 토큰 상한 | 64 | 256 |
| 읽을 출력 | 답과 근거 | 보이는 풀이, 최종 답, 종료 상태 |
| 공통 조건 | CPU, 같은 원문·질문, 학습 없음 | CPU, 같은 원문·질문, 학습 없음 |

두 모델 모두 Apache-2.0 공개 모델. CPU 실습을 위해 작은 모델 선택. 공개 모델 카드의 권고에 따라 추론형은 샘플링 설정 사용.

- 일반 모델의 **zero-shot** 결과와 추론형의 예시 없는 결과 비교
- 일반 모델의 few-shot은 예시 유무 비교에 별도로 사용
- 모델 크기, 학습, 세대, 생성 설정이 서로 다른 조건
- 출력 차이를 **추론형 방식 하나만의 효과**로 단정하지 않는 비교
- 이 질문 몇 개로 두 모델의 전체 성능 순위나 실무 적합성 판단 불가

#### 풀이 도중 끝나면 어떻게 읽는가

CPU 비용을 제한하려면 생성 길이 상한 필요. 추론형 모델이 풀이만 쓰다가 상한에 도달할 수 있는 상태.

- `</think>`: 이번 모델에서 풀이가 끝나는 경계 표시
- 경계 전 종료: 최종 답 없음, `answer=None`, `status: truncated`
- 경계 뒤 답도 중간에 잘릴 가능성: 원문 출력과 종료 상태 함께 확인
- 도중 풀이를 최종 답으로 옮겨 적지 않는 원칙
- 상한 도달은 이번 실행의 제약, 해당 모델이 항상 답하지 못한다는 뜻과 구분

#### Q4: 그럴듯한 답과 맞는 답의 구분

관광객에게 안내할 답이 자연스럽게 들리는지보다 **각 주장을 뒷받침하는 자료가 있는지** 먼저 확인.

<FigureFrame src="/interactive/week-11/evidence-check.html" title="공개 원문에 근거가 있는 주장과 없는 주장 분류" height="370px" />

| 답의 주장 | 발췌에서 확인할 것 | 처리 |
|---|---|---|
| 길이는 11km | `11-kilometer` | 원문 발췌에 근거 있는 답 |
| 입장 요금은 무료 | 발췌에 요금 없음 | 미확인, 공식 요금 자료 대조 필요 |
| 해안·도심 구간 포함 | `coastal and urban trail` | 원문 발췌에 근거 있는 답 |
| 오늘도 같은 조건 | 발췌만으로 현재 운영 확인 불가 | 최신 운영 자료 대조 필요 |

원문에 있는 숫자도 최신 운영 정보 보증과는 구분. 실습의 정답 기준은 **이 발췌에 대한 답변**이며 실제 여행 계획은 최신 공식 안내 확인 필요.

열람한 같은 페이지에서도 상단 설명은 13.3km, 상세 본문은 11km로 표기가 다른 상태. 모델이 발췌의 11km를 되풀이했다고 실제 최신 코스 길이를 검증한 것은 아님. 원문 간 불일치가 있으면 추가 확인 전 판단 보류.

#### 환각 사례의 구분

환각은 모델이 사실과 다르거나 제공된 근거로 뒷받침되지 않는 내용을 생성한 경우를 가리키는 표현. 답이 틀린 이유를 하나로 단정하기보다 입력·출력·근거를 함께 보존.

- 없는 값 생성: 원문에 없는 요금을 임의 제시
- 원문 오독: 길이 11을 다른 숫자로 변경
- 출처 왜곡: 실제로 읽지 않은 자료를 근거로 제시
- 오래된 정보: 과거 정보를 현재 조건처럼 안내
- 확인 보류: 근거 자료가 없어 참·거짓을 아직 판단하지 못하는 상태

**미확인과 거짓은 구분.** 요금 자료가 없다는 이유만으로 실제 요금 주장 자체가 거짓이라고 단정 불가. 다만 이 원문에 근거한 답변이라는 조건은 충족하지 못한 상태.

#### 강의 2에서 꼭 가져갈 것

1. 보이는 풀이와 정확한 답의 구분
2. 길이 제한으로 최종 답이 없는 실행의 표시
3. 두 모델의 여러 조건 차이와 비교 해석의 한계
4. 주장별 원문 근거 대조와 미확인 정보의 안내 보류

### 학습활동

- 모델 출력에서 사실과 다른 답 또는 원문에 근거 없는 주장 1건 수집
- 질문, 입력 원문, 실제 출력, 대조 자료 함께 보존
- 틀린 숫자·없는 값·출처 왜곡·최신성 문제 중 해당 유형 기록
- 해당 사례가 나오지 않으면 실제 출력의 근거 있는 주장 1건과 미확인 처리 1건 기록
- 없는 환각 사례를 실제 모델 결과처럼 만들지 않는 원칙

### 출력 읽는 법

- `status: ok`: 추론 결과 반환. 사실성 확인을 통과했다는 뜻과 구분
- `raw`: 모델이 실제 생성한 텍스트
- `visible_process`: 추론형의 보이는 풀이, 내부 상태 증명과 구분
- `answer`: 풀이 종료 경계 뒤 답. 경계가 없으면 None
- `new_tokens`, `budget`: 새 토큰 수와 생성 상한
- `status: truncated`: 불완전 출력. 풀이 경계 전 종료면 최종 답 미완료
- `status: unavailable`: 설치·다운로드·추론 실패. 모델 결과 없음

| 증상 | 기록과 다음 조치 |
|---|---|
| 모델 다운로드가 오래 걸림 | 실행 대기, 중복 실행 금지 |
| unavailable | 실제 오류 보존, 연결·설치·메모리 확인 후 재실행 |
| 풀이만 있고 답 없음 | truncated 표시, 미완료를 정답으로 대체 금지 |
| 예시를 넣어도 답 변화 없음 | 실제 결과로 기록, 개선을 지어내지 않음 |
| 요금을 무료로 답함 | 근거 없는 주장 분류, 공식 요금 자료 대조 전 안내 보류 |

## 확인 질문과 답

<details>
<summary>Q1. few-shot 예시를 넣으면 모델을 새로 학습한 것인가?</summary>

아님. 현재 입력 안에 예시를 넣어 참고하게 하는 방식. 모델 내부의 숫자를 업데이트하는 미세조정과 구분.

</details>

<details>
<summary>Q2. 추론형 모델의 풀이가 길면 더 정확한가?</summary>

길이 자체로 판단 불가. 최종 답과 각 주장을 원문·정답 기준으로 대조. 보이는 풀이가 내부 상태의 충실한 기록이라는 보장도 없음.

</details>

<details>
<summary>Q3. 풀이 도중 토큰 상한에 도달한 경우의 결과는?</summary>

truncated, 최종 답 미완료로 기록. 도중 풀이를 최종 답으로 채점하거나 사람이 만든 답으로 채우지 않는 처리.

</details>

<details>
<summary>Q4. 원문에 없는 요금을 무료라고 답하면 어떻게 다룰 것인가?</summary>

원문 근거 없는 주장으로 기록. 실제 요금의 참·거짓은 별도 공식 자료 대조 필요. 확인 전 관광객 안내 보류, 발췌에 근거한 실습 답은 UNKNOWN.

</details>

## 이번 주 용어 정리

| 용어 | 한 줄 뜻 |
